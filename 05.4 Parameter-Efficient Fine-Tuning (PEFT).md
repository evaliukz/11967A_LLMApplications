# 5.6 --- Parameter-Efficient Fine-Tuning (PEFT)

> **一句话主线：** Full fine-tuning 是"把整个大模型都重新调一遍"；PEFT
> 是"把 pretrained model
> 大部分甚至全部冻住，只训练很小的一部分参数，也尽量让模型学会新任务"。

------------------------------------------------------------------------

## 0. 先把这一章放回整门课的主线

前面几节其实一直在回答同一个问题：

> **我已经有一个 pretrained LLM，怎么让它适应我的 task？**

``` text
Pretrained LLM
      │
      ├── Prompting / In-Context Learning
      │     不训练 weights
      │     把 instruction / examples 放进 context
      │
      ├── Automatic Prompt Optimization
      │     model 不动
      │     自动寻找更好的 prompt
      │
      ├── PEFT
      │     真的训练
      │     但只训练很少的 parameters
      │
      └── Full Fine-Tuning
            训练整个 / 大部分 model
```

所以 PEFT 位于：

``` text
Prompting  ←──────── PEFT ────────→  Full Fine-Tuning
改得少                               改得多
便宜                                 贵
```

------------------------------------------------------------------------

# 1. 为什么需要 PEFT？

假设有一个 10B-parameter model，要做三个任务：

``` text
Task A: medical summarization
Task B: sentiment classification
Task C: legal QA
```

## Full Fine-Tuning 的思路

每个 task 都把整个模型重新训练：

``` text
Base Model
   ├── Fine-tune all weights → Medical Model
   ├── Fine-tune all weights → Sentiment Model
   └── Fine-tune all weights → Legal Model
```

问题是每个 task 都可能需要保存一整套 task-specific weights。

模型越大：

``` text
training cost ↑
GPU memory ↑
storage ↑
deployment complexity ↑
```

如果有 100 个 customers / tasks：

``` text
100 tasks
×
one giant fine-tuned model per task
```

成本会非常高。

------------------------------------------------------------------------

# 2. PEFT 的核心思想

PEFT 问：

> **真的有必要为了一个新 task，把几十亿甚至几百亿个 parameters
> 全部改掉吗？**

也许 pretrained model 已经学会了绝大多数：

-   language structure
-   syntax
-   semantics
-   world knowledge
-   general representations

新 task 只需要告诉它：

> "已有能力应该怎么重新组合、怎么用于这个任务。"

于是：

``` text
Pretrained Model
99%+ parameters frozen
        │
        ↓
只训练一个很小的 task-specific 部分
```

目标：

``` text
Much fewer trainable parameters
        ↓
less training memory
less task-specific storage
easier task switching
while preserving useful performance
```

------------------------------------------------------------------------

# 3. 一个很重要的区分：Trainable Parameters vs Total Parameters

PEFT 并不是把一个 10B model 变成 10M model。

Base model 仍然可能是：

``` text
10 billion parameters
```

只是训练时：

``` text
Frozen:
9,990,000,000

Trainable:
10,000,000
```

所以 PEFT 主要减少的是：

> **需要更新、保存为 task-specific adaptation 的参数量。**

它并不自动意味着 base model inference 本身变得很小。

------------------------------------------------------------------------

# 4. PEFT 三大家族

课程把 PEFT 分成三类：

``` text
                    PEFT
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
    Addition     Specification  Reparameterization
```

最简单的大白话：

``` text
Addition
= 原模型不动，我 ADD 一点新的东西训练

Specification
= 不加东西，我 SPECIFY 原模型里少数参数训练

Reparameterization
= 不直接训练巨大 update，
  用更低维、更紧凑的形式表示它
```

------------------------------------------------------------------------

# 5. Category 1 --- Addition

定义：

> **增加新的 trainable parameters，同时冻结 pretrained model 原来的
> parameters。**

代表：

-   Prompt Tuning
-   Prefix Tuning
-   Adapters
-   Compacter（adapter 的更高效扩展）

脑内图：

``` text
Frozen Base Model
      +
small trainable component
```

------------------------------------------------------------------------

# 6. Prompt Tuning：不要寻找单词，直接学习 Embeddings

这是最容易和普通 prompt engineering 搞混的地方。

## 普通 Prompt Engineering

你写：

``` text
"Summarize the following article:"
```

这些是真实 tokens。

``` text
text
↓
token IDs
↓
embeddings
```

你是在 **discrete token space** 中选 prompt。

------------------------------------------------------------------------

## Prompt Tuning 的问题

理想上我们想：

``` text
找到一串最好的 prompt tokens
→ prepend 到 task input
→ model 就会做好 task
```

但是：

> **直接在 discrete tokens 上 optimization 很困难。**

Vocabulary 是离散的：

``` text
token 42
token 391
token 8231
...
```

Gradient descent 更擅长优化连续数值。

------------------------------------------------------------------------

# 7. Prompt Tuning 的关键转变

所以不再问：

> "哪个英文词最好？"

而是直接训练：

``` text
e1, e2, e3, e4, e5
```

这些是 continuous embedding vectors。

输入变成：

``` text
[learned embedding 1]
[learned embedding 2]
[learned embedding 3]
[learned embedding 4]
       +
real input embeddings
       ↓
Frozen Transformer
```

例如真实输入：

``` text
The hippo ate my homework.
```

普通 embedding：

``` text
E(The), E(hippo), E(ate), E(my), E(homework)
```

Prompt tuning：

``` text
P1 P2 P3 P4 P5
+
E(The) E(hippo) E(ate) E(my) E(homework)
```

训练时：

``` text
Base LLM weights = frozen
P1...P5 = trainable
```

------------------------------------------------------------------------

# 8. Soft Prompt 为什么可能看不懂？

因为 `P1` 不需要等于：

``` text
E("summarize")
```

它可能只是 embedding space 中的某个 vector：

``` text
P1 = [0.31, -0.72, 1.04, ...]
```

不一定对应 vocabulary 中任何真实 token。

所以：

> **Prompt tuning 学到的是 virtual / soft tokens，不是人类可读的
> prompt。**

------------------------------------------------------------------------

# 9. Prompt Tuning vs Prompt Engineering

                              Prompt Engineering    Prompt Tuning
  --------------------------- --------------------- ----------------------
  Prompt 是什么               Human-readable text   Trainable embeddings
  Discrete / Continuous       Discrete              Continuous
  Gradient training           No                    Yes
  Base model weights          Frozen                Frozen
  人能读懂吗                  Yes                   Usually no
  需要 training examples 吗   不一定                Yes

一句话：

``` text
Prompt Engineering
= 人找 words

Prompt Tuning
= gradient 找 vectors
```

------------------------------------------------------------------------

# 10. Prompt Tuning Paper：Lester et al. 2021

**The Power of Scale for Parameter-Efficient Prompt Tuning**

论文核心问题：

> 能不能只训练一小段 soft prompt，而把整个 language model 冻住？

答案是：可以，而且 **model 越大，prompt tuning 越有竞争力**。

论文在 T5 不同规模上实验，发现随着 pretrained model 进入
billion-parameter scale，prompt tuning 和 full model tuning 的
performance gap 明显缩小。

### 大白话

小模型：

``` text
Base model 自己能力有限
→ 只给几个 learned vectors
→ 很难弥补全部能力缺口
```

超大 pretrained model：

``` text
很多能力已经在 model 里面
→ soft prompt 更像“遥控器”
→ 只需要把已有能力引导出来
```

### 论文最值得记的结论

> **Prompt tuning becomes more competitive as model scale increases.**

论文还报告 soft prompt 对 domain transfer 有一定 robustness 优势。\
来源：Lester, Al-Rfou & Constant, EMNLP 2021.

Paper: https://aclanthology.org/2021.emnlp-main.243/

------------------------------------------------------------------------

# 11. Prefix Tuning：Prompt Tuning 的"深入每一层版"

课程里的核心描述：

> Same idea as prompt tuning, except that the learned prefix is appended
> not just to the input embeddings, but rather at each layer of the
> Transformer.

大白话：

Prompt tuning：

``` text
soft prompt
   ↓
只从模型入口进去
   ↓
Layer 1
Layer 2
Layer 3
...
```

Prefix tuning：

``` text
Layer 1 ← learned prefix
Layer 2 ← learned prefix
Layer 3 ← learned prefix
Layer 4 ← learned prefix
...
```

所以可以粗略记：

``` text
Prompt Tuning
= 在门口给模型塞“小抄”

Prefix Tuning
= 每一层 Transformer 都给“小抄”
```

更严格地说，prefix tuning 让后续 tokens 能在 Transformer 的层内
attention computation 中 attend 到 learned continuous prefix / virtual
tokens。

------------------------------------------------------------------------

# 12. Prefix Tuning Paper：Li & Liang 2021

**Prefix-Tuning: Optimizing Continuous Prompts for Generation**

论文冻结 pretrained LM，只优化 task-specific continuous prefix。

实验：

``` text
GPT-2
→ table-to-text generation

BART
→ summarization
```

论文报告仅学习大约 **0.1% parameters** 时：

-   full-data setting 可获得与 full fine-tuning comparable 的表现；
-   low-data settings 中可以优于 full fine-tuning；
-   对 training 中未见 topic 的 examples 有更好的 extrapolation。

### 最重要直觉

> Base model 是一台已经很强的机器，prefix
> 不重新造机器，而是学习一套很小的"控制信号"。

Paper: https://aclanthology.org/2021.acl-long.353/

------------------------------------------------------------------------

# 13. Prefix / Prompt 应该怎么 Initialize？

课程 slide 的经验结果：

> **Initializing to real embeddings seems to work better than random
> initialization.**

也就是说：

``` text
Option A:
P1...Pn = completely random vectors

Option B:
P1...Pn = embeddings of real words
```

例如：

``` text
"active"
"elephant"
"summarize"
...
```

然后再让 gradient optimization 修改。

实验图中 random initialization 整体较差，而从 real token embeddings
初始化通常更好。

直觉上：

``` text
random vector
→ embedding space 里可能是奇怪的起点

real word embedding
→ 从 pretrained model 已经熟悉的 representation 起步
```

注意：初始化成真实词之后，训练得到的最终 vectors
仍不需要继续对应这些词。

------------------------------------------------------------------------

# 14. Prompt / Prefix Tuning 的 Advantages

课程列出的第一个优势：

> learned embeddings 很小，可能只有几 MB 或更少。

所以可以：

``` text
One giant frozen base model
         │
         ├── Prompt A: Medical
         ├── Prompt B: Legal
         ├── Prompt C: Finance
         └── Prompt D: Customer X
```

不用存：

``` text
4 × giant model
```

而是：

``` text
1 × giant base model
+
4 × tiny task-specific embeddings
```

------------------------------------------------------------------------

# 15. Hotswapping：从 Systems 角度理解

这是 PEFT 非常有工程价值的地方。

Server memory 中：

``` text
            Frozen Base LLM
                 │
      ┌──────────┼──────────┐
      ↓          ↓          ↓
 Task A      Task B      Task C
 embedding   embedding   embedding
```

请求来了：

``` text
Medical request
→ load medical prompt parameters

Legal request
→ swap in legal prompt parameters
```

Base model 不需要重新加载一整份。

这也是 PEFT 在：

-   multi-tenant serving
-   personalization
-   domain specialization

中很有吸引力的原因。

------------------------------------------------------------------------

# 16. Prompt / Prefix Tuning 的 Pitfalls

课程强调三个问题。

### 1. Convergence 可能比 Full Fine-Tuning 慢

虽然 trainable parameters 少：

``` text
≠ 一定更容易 optimization
```

课程指出实践中这些方法可能比 full parameter fine-tuning 收敛明显更慢。

------------------------------------------------------------------------

### 2. Prefix Length 不好选

假设：

``` text
prefix length = 100 tokens
```

context window：

``` text
4096
```

那真实 task 可以使用的 sequence positions 就减少。

``` text
prefix positions
+
actual input positions
≤ context capacity
```

所以：

``` text
long prefix
→ more adaptation capacity
→ but consumes more sequence positions

short prefix
→ cheaper
→ but possibly insufficient capacity
```

没有一个所有 tasks 通用的最佳长度。

------------------------------------------------------------------------

### 3. Learned Embeddings 不可解释

``` text
P1 = [0.2, -1.7, 0.03, ...]
```

你无法简单问：

> "这句话是什么意思？"

因为它不是一句话。

------------------------------------------------------------------------

# 17. Adapters：在 Transformer 里面插"小模块"

Prompt/prefix tuning：

``` text
在 representations / prefixes 上加 trainable vectors
```

Adapter 的想法：

> **直接在 pretrained network 的层之间插入小 neural-network modules。**

Base weights：

``` text
FROZEN
```

Adapters：

``` text
TRAINABLE
```

------------------------------------------------------------------------

# 18. Adapter 的结构

经典 adapter 可以粗略理解成：

``` text
hidden state
    │
    ↓
Down Projection
d_model → d_small
    │
    ↓
Nonlinearity
    │
    ↓
Up Projection
d_small → d_model
    │
    ↓
add / residual path
```

也就是：

``` text
big vector
↓
压缩到小空间
↓
做 transformation
↓
再投影回原来的维度
```

数学直觉：

\[ h `\rightarrow `{=tex}W\_{down}h
`\rightarrow `{=tex}`\sigma`{=tex}(W\_{down}h)
`\rightarrow `{=tex}W\_{up}`\sigma`{=tex}(W\_{down}h) \]

真正 train 的主要就是 adapter 中这些小 matrices。

------------------------------------------------------------------------

# 19. 为什么 Down-Project 再 Up-Project？

假设 Transformer hidden size：

``` text
d_model = 4096
```

如果新加一个：

``` text
4096 × 4096
```

matrix，那还是非常大。

Adapter 可以：

``` text
4096
 ↓
64
 ↓
4096
```

参数量大致：

``` text
4096 × 64
+
64 × 4096
```

远小于：

``` text
4096 × 4096
```

所以 bottleneck：

``` text
d_small << d_model
```

是 parameter efficiency 的关键。

------------------------------------------------------------------------

# 20. 为什么 Adapter 初始化要"像没插一样"？

课程说：

> adapters are initialized so that the output of the adapter-inserted
> module resembles the original model.

原因很直观。

你已经有：

``` text
well-trained pretrained model
```

如果刚插 adapter 就随机大幅改变 hidden states：

``` text
original useful representation
→ destroyed
```

所以希望训练开始时：

``` text
Adapter ≈ near-identity / near-zero perturbation

Model + Adapter
≈
Original Model
```

然后慢慢学习 task-specific modification。

------------------------------------------------------------------------

# 21. Adapter Paper：Houlsby et al. 2019

**Parameter-Efficient Transfer Learning for NLP**

这是 adapter 经典论文之一。

核心：

``` text
Frozen pretrained model
+
small task-specific adapter modules
```

在 BERT 上测试 26 个 text classification tasks。

论文报告：

``` text
Full fine-tuning:
train 100% parameters per task

Adapters:
add about 3.6% parameters per task
```

在 GLUE 上，adapter performance 距 full fine-tuning 大约 **0.8%**。

### 论文最重要的系统意义

以前：

``` text
Task A → full model A
Task B → full model B
Task C → full model C
```

Adapters：

``` text
                 Shared BERT
                /    |     \
          Adapter A Adapter B Adapter C
```

所以：

> **共享 expensive base model，只保存小的 task-specific modules。**

Paper: https://proceedings.mlr.press/v97/houlsby19a.html

------------------------------------------------------------------------

# 22. Compacter：让 Adapter 再小一点

课程接下来问：

> Adapter 已经小了，还能不能更 parameter-efficient？

标准 adapter 仍包含 fully connected matrices：

\[ y = W_2,`\mathrm{GELU}`{=tex}(W_1x+b_1)+b_2 \]

虽然 `W1` / `W2` 比原模型矩阵小，但仍可能有很多参数。

Compacter 的想法：

> **不要完整学习这些 dense matrices，用更紧凑的结构来表示它们。**

它结合：

-   adapters
-   low-rank optimization
-   parameterized hypercomplex multiplication
-   parameter sharing

论文中利用 Kronecker-product-based parameterization 压缩 adapter
weights。

课程 slide 的核心结论：

> adapter-layer parameter count 可以大幅减少，同时尽量保持 performance。

------------------------------------------------------------------------

# 23. Compacter Paper 高度总结

**Compacter: Efficient Low-Rank Hypercomplex Adapter Layers**

核心问题：

``` text
Adapters 很省
但还能不能更省？
```

方法：

``` text
普通 dense adapter matrices
↓
structured / low-rank / hypercomplex parameterization
↓
far fewer task-specific parameters
```

论文报告仅训练 pretrained model 大约 **0.047%** 的
parameters，仍在其评测设置中取得与 standard fine-tuning 有竞争力的表现。

不需要为了这门课深挖 hypercomplex algebra。

考试层面记：

> **Compacter = 更 parameter-efficient 的 adapter variant，通过
> structured factorization / parameter sharing 减少 adapter
> parameters。**

Paper: https://arxiv.org/abs/2106.04647

# 24. Category 2 --- Specification Methods

Addition 是：

``` text
base parameters frozen
+
ADD new trainable parameters
```

Specification 不一样：

> **不一定加新 module，而是从原模型已有 parameters
> 中挑一小部分训练，其余冻结。**

``` text
Original parameters:

████████████████████████████████

Only selected parameters train:

░░░░░░░░████░░░░░░░░░██░░░░░░
```

课程给三种：

1.  Layer Freezing
2.  Bias Terms Fine-Tuning / BitFit
3.  Diff Pruning

------------------------------------------------------------------------

# 25. Layer Freezing

最直观。

假设：

``` text
Transformer Layer 1
Layer 2
Layer 3
...
Layer 24
```

可以：

``` text
Layers 1–20 → frozen
Layers 21–24 → trainable
```

为什么可能有效？

不同 layers 往往学到不同层次的信息；早期/中间/后期 representation
的角色可能不同。

因此可以只 fine-tune 后面的部分。

### 问题

粒度很粗：

``` text
一个 Transformer layer
```

本身就可能包含大量 parameters。

所以：

> **即使只解冻一层，也可能还是很贵。**

------------------------------------------------------------------------

# 26. Layer Analysis Paper：Tenney et al. 2019

课程链接到关于 BERT 层级信息的工作。

这类研究的重要观察是：

> pretrained contextual representations 的不同层会表现出不同类型的
> linguistic information。

因此产生一种直觉：

``` text
不一定所有 layers 都需要针对 downstream task 同等程度地更新
```

对 PEFT 的意义：

> 可以尝试 freeze 大量 layers，只更新少数 layers。

这里不要理解成"第 N 层永远只负责某一种语法功能"；更准确地说，不同层的
representation 对不同 linguistic phenomena 呈现不同程度的信息。

Paper: https://aclanthology.org/P19-1452/

------------------------------------------------------------------------

# 27. BitFit：只训练 Bias

Linear layer：

\[ y = Wx + b \]

Full fine-tuning：

``` text
train W
train b
```

BitFit：

``` text
freeze W
train b
```

为什么省？

如果：

``` text
W = 4096 × 4096
```

那么 W 有约 16.8M values。

但：

``` text
b = 4096
```

小得多。

所以只训练 bias，可以极大减少 trainable parameters。

------------------------------------------------------------------------

# 28. BitFit Paper 高度总结

**BitFit: Simple Parameter-efficient Fine-tuning for Transformer-based
Masked Language-models**

核心思想：

> **只修改 model 中 bias terms（或其中一部分）。**

论文在 pretrained BERT models 上发现，在 small-to-medium training data
场景中，BitFit 可以与 full fine-tuning
具有竞争力，有时甚至更好；在较大数据场景中也能与其他 sparse fine-tuning
方法竞争。

论文还提出一个有趣解释：

> fine-tuning 的一部分作用可能不是"重新学习大量语言知识"，而是在让
> pretrained model 已有的知识更适合当前 task。

Paper: https://aclanthology.org/2022.acl-short.1/

------------------------------------------------------------------------

# 29. Diff Pruning

这个名字容易误解。

它不是简单说：

> "随便挑几个 weights 训练。"

它把 adapted model 想成：

\[ `\theta`{=tex}*{`\text{task}`{=tex}} =
`\theta`{=tex}*{`\text{pretrained}`{=tex}} +
`\Delta`{=tex}`\theta`{=tex}\_{`\text{task}`{=tex}} \]

其中：

``` text
θ_pretrained = frozen shared base
Δθ_task      = task-specific changes
```

然后要求：

``` text
Δθ_task 尽量 sparse
```

也就是说：

> **让算法自己发现哪些少数 parameters 真正需要发生变化。**

------------------------------------------------------------------------

# 30. Diff Pruning Paper 高度总结

**Parameter-Efficient Transfer Learning with Diff Pruning**

方法：

``` text
Frozen pretrained weights
+
learned task-specific diff vector
```

训练时通过 differentiable approximation to an **L0-style sparsity
penalty** 鼓励：

``` text
大部分 Δθ = 0
```

最终只保存少量 nonzero task-specific changes。

论文报告在 GLUE 上，仅修改约 **0.5%** pretrained parameters per task
时，可以匹配 full-finetuned baselines 的表现。

### 大白话

Full fine-tuning：

``` text
“所有员工都重新培训。”
```

Diff Pruning：

``` text
“让系统自己找出真正需要重新培训的那 0.x% 员工。”
```

Paper: https://aclanthology.org/2021.acl-long.378/

# 31. Category 3 --- Reparameterization

这是 LoRA 所在的家族，也是这章最值得深入理解的部分。

核心问题：

> **模型有几十亿 parameters，但为了适应一个
> task，真正需要改变的自由度会不会其实很低？**

这就引出：

> **Low Intrinsic Dimension**

------------------------------------------------------------------------

# 32. 什么叫 Low Intrinsic Dimension？

假设模型有：

``` text
1,000,000,000 parameters
```

Full fine-tuning 表面上允许：

``` text
1 billion dimensions
```

都改变。

但真正达到某个 downstream task 所需的 useful
update，也许主要落在一个很小的低维空间里。

类比：

一个人在三维房间里走：

``` text
理论上可以：
x, y, z

但如果他始终在地板上：
真正运动自由度≈x,y
```

虽然 ambient space 是 3D，实际 useful movement 是低维的。

------------------------------------------------------------------------

# 33. Intrinsic Dimension Paper 高度总结

**Intrinsic Dimensionality Explains the Effectiveness of Language Model
Fine-Tuning**

论文核心观点：

> pretrained language model 的 task adaptation 可能存在一个远低于 full
> parameter count 的 effective / intrinsic dimension。

一个非常有冲击力的实验结果是：论文报告对 RoBERTa 在 MRPC 上进行
low-dimensional random-subspace optimization 时，仅优化约 **200
trainable parameters** 的一种设置就能达到 full-parameter performance
的约 90%。

这并不是说：

> "所有任务只需要 200 parameters。"

而是说明：

> **模型的 parameter space 虽然巨大，task adaptation
> 所需要探索的有效方向可能少得多。**

这给 LoRA 等 reparameterization methods 提供了很强的直觉基础。

Paper: https://arxiv.org/abs/2012.13255

------------------------------------------------------------------------

# 34. LoRA：这一章最重要的方法

LoRA：

> **Low-Rank Adaptation**

先看 full fine-tuning。

假设某个 pretrained matrix：

\[ W_0 \]

Full fine-tuning 后：

\[ W = W_0 + `\Delta `{=tex}W \]

其中：

\[ `\Delta `{=tex}W \]

可能是一个巨大 matrix。

LoRA 的假设：

> **我们不需要自由地学习整个巨大 ΔW；这个 update 可以用 low-rank
> matrices 表示。**

------------------------------------------------------------------------

# 35. LoRA 的核心公式

LoRA：

\[ W = W_0 + BA \]

其中：

\[ W_0 `\text{ frozen}`{=tex} \]

而：

\[ A, B `\text{ trainable}`{=tex} \]

如果：

\[ W_0 `\in `{=tex}`\mathbb{R}`{=tex}\^{d `\times `{=tex}k} \]

则可以令：

\[ A `\in `{=tex}`\mathbb{R}`{=tex}\^{r `\times `{=tex}k} \]

\[ B `\in `{=tex}`\mathbb{R}`{=tex}\^{d `\times `{=tex}r} \]

并且：

\[ r `\ll `{=tex}d,k \]

于是：

\[ BA `\in `{=tex}`\mathbb{R}`{=tex}\^{d `\times `{=tex}k} \]

正好能作为：

\[ `\Delta `{=tex}W \]

------------------------------------------------------------------------

# 36. LoRA 为什么省这么多参数？

假设：

``` text
W = 4096 × 4096
```

Full update：

``` text
4096 × 4096
= 16,777,216 parameters
```

如果 LoRA：

``` text
rank r = 8
```

则：

``` text
A: 8 × 4096
B: 4096 × 8
```

总参数：

``` text
32,768 + 32,768
= 65,536
```

对比：

``` text
Full ΔW:
16,777,216

LoRA:
65,536
```

大约只需要 full matrix update 的：

``` text
0.39%
```

这就是 low-rank factorization 的力量。

------------------------------------------------------------------------

# 37. LoRA 大白话类比

假设你要描述一个 4000 × 4000 的巨大变化表。

Full fine-tuning：

> "1600 多万个格子，我每个格子都单独告诉你怎么改。"

LoRA：

> "这些变化其实高度有规律。我只给你两个很瘦的小表 A 和
> B，你把它们乘起来，就恢复出整个 update。"

``` text
Small A
   ×
Small B
   ↓
Large ΔW
```

# 38. LoRA 的 Forward Pass

原来：

\[ h = W_0x \]

LoRA：

\[ h = W_0x + BAx \]

其中：

``` text
W0 = frozen
A,B = trainable
```

训练时 gradient 只更新：

``` text
A
B
```

而不更新：

``` text
W0
```

# 39. LoRA 和 Adapter 到底哪里不同？

它们看起来很像：

> 都增加少量 trainable parameters。

但概念上：

### Adapter

显式增加一个新的 nonlinear network path：

``` text
h
↓
down projection
↓
nonlinearity
↓
up projection
↓
add back
```

### LoRA

对已有 linear transformation 的 **weight update** 做 low-rank
parameterization：

``` text
W0
+
BA
```

所以：

``` text
Adapter
= add a small neural module

LoRA
= represent weight update as low-rank matrices
```

这是非常值得面试时说清楚的区别。

# 40. LoRA Paper 高度总结

**LoRA: Low-Rank Adaptation of Large Language Models**

论文 motivation：

Full fine-tuning 巨型 LMs 需要：

``` text
train/store huge task-specific parameter sets
```

LoRA：

``` text
freeze pretrained weights
+
inject trainable low-rank decomposition matrices
```

论文在 RoBERTa、DeBERTa、GPT-2、GPT-3 等模型上实验，报告 LoRA 能在远少于
full fine-tuning trainable parameters 的情况下达到 comparable /
sometimes better task quality。

论文以 GPT-3 175B 的 Adam fine-tuning 为例，报告可将 trainable parameter
count 降低约 **10,000×**，GPU memory requirement 降低约
**3×**。论文也强调，相比某些 adapter designs，LoRA 的 updates 可以合并进
base weights，因此不必增加额外 inference latency。

### 最值得记住

> **Task-specific update matrices often do not need full rank.**

因此：

``` text
Huge ΔW
≈
B × A
```

Paper: https://arxiv.org/abs/2106.09685

# 41. QLoRA：LoRA 再解决一个问题

LoRA 虽然只训练很少 parameters，但：

> **Frozen base model 本身还是很大。**

比如：

``` text
65B parameters
```

即使不训练它：

``` text
仍然要把它放进 GPU memory
```

QLoRA 的核心：

``` text
Base model
→ quantize to 4-bit
→ keep frozen

LoRA adapters
→ train
```

也就是：

``` text
Quantization
+
LoRA
=
QLoRA
```

# 42. QLoRA Paper 高度总结

**QLoRA: Efficient Finetuning of Quantized LLMs**

核心做法：

``` text
Frozen 4-bit quantized pretrained model
+
trainable LoRA adapters
```

论文引入/使用几项 memory-saving techniques：

-   4-bit NormalFloat (NF4)
-   double quantization
-   paged optimizers

论文报告：

> 可以在单张 **48GB GPU** 上 fine-tune 一个 **65B parameter
> model**，同时在其实验中保持与 16-bit full fine-tuning 相当的 task
> performance。

### 最重要区别

``` text
LoRA:
减少 TRAINABLE parameters

QLoRA:
LoRA
+
quantize frozen BASE MODEL
→ 进一步减少 memory footprint
```

Paper: https://arxiv.org/abs/2305.14314


# 50. Which Method Should I Use?

按照课程 framing：

### 如果 resources 足够，而且追求 task-specific performance

``` text
Full Fine-Tuning
```

通常仍然是很强的 baseline / option。

### 如果需要大量 task/customer specialization

``` text
PEFT
```

特别有价值，因为 task-specific storage 很小。

### Prompt / Prefix Tuning

优点：

``` text
极少参数
易于保存和 swap
```

缺点：

``` text
可能 convergence 慢
prefix length 难选
soft embeddings 不可解释
```

### Adapters

优点：

``` text
strong parameter efficiency
modular
task-specific modules easy to store
```

缺点：

``` text
改变 computation graph
某些实现可能增加 inference overhead
```

### LoRA

核心优势：

``` text
very few trainable parameters
strong empirical performance
simple low-rank idea
updates can often be merged for inference
```

因此课程指出 LoRA 及其后续方法（如 QLoRA）已经成为非常常见的 PEFT 路线。

# 52. 面试级 LoRA Explanation

如果面试官问：

> **What is LoRA and why does it work?**

可以答：

> LoRA is a parameter-efficient fine-tuning technique that freezes the
> pretrained model weights and represents the task-specific weight
> update using two trainable low-rank matrices. Instead of learning a
> full update matrix (`\Delta `{=tex}W), LoRA parameterizes it as
> (`\Delta `{=tex}W = BA), where the rank (r) is much smaller than the
> original dimensions. This substantially reduces the number of
> trainable and task-specific parameters while preserving the expressive
> capacity needed for many downstream adaptations.

如果追问 intuition：

> The intuition is that although the model's parameter space is
> extremely high-dimensional, the useful task-specific update may lie in
> a much lower-dimensional subspace.

## Q5. Why does LoRA reduce parameters?

因为：

\[ r `\ll `{=tex}d,k \]

所以：

``` text

LoRA parameters = r × (d + k)
```

# 55. 这一章真正应该带走的思想

不要把 PEFT 理解成一堆零散 tricks。

它背后的统一问题是：

> **A pretrained LLM already contains enormous capability. How many
> degrees of freedom do we actually need to change to adapt that
> capability to a new task?**

Full fine-tuning 的答案：

``` text
Potentially all parameters.
```

PEFT 的答案：

``` text
Maybe far fewer.
```

于是产生三种路线：

``` text
I can ADD a tiny component.
I can SELECT a tiny subset.
I can REPRESENT the update in a tiny low-dimensional space.
```

而 LoRA 最漂亮的地方就在于把第三种思想变成：

\[ `\boxed{\Delta W = BA}`{=tex} \]

这一个公式几乎就是整章 **Reparameterization PEFT** 的核心。
