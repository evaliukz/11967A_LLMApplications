## LLM 自动评估常见任务与指标


> 这一讲的主线不是"背公式"，而是理解：**模型输出长什么样，决定了我们应该怎么评价它。**

最重要的地图：

``` text
Language Model Evaluation
│
├── Classification        → 一个 label
├── Sequence Generation   → 一段 sequence
├── Ranking               → 一个排序
└── Composite Evaluation  → 多个任务 / metric 综合
```

对于 **sequence generation**，课程重点介绍：

``` text
Perplexity
Exact Match
Word Error Rate (WER)
BLEU
ROUGE
```

它们其实是在逐渐回答不同的问题：

``` text
Perplexity:
模型觉得真实文本有多“意外”？

Exact Match:
生成结果和标准答案一模一样吗？

WER:
和标准答案相比，要改多少个词？

BLEU:
我生成出来的词 / n-gram，有多少在参考答案里？
→ 更偏 Precision

ROUGE:
参考答案里的词 / n-gram，有多少被我覆盖到了？
→ 更偏 Recall
```

------------------------------------------------------------------------

# 1. Automatic Evaluation 的通用形式

课件给出的 general form：

$$
\mu(x, \tilde{y}, D_x)
$$

三个东西分别是：

``` text
x        = instance / input
ỹ        = system prediction
D_x      = test information about x
μ(...)   = evaluation metric
```

大白话：

> **给模型一个题 x，模型交一份答案 ỹ，再拿测试集提供的标准信息 Dₓ 来给它打分。**

<img width="1016" height="445" alt="image" src="https://github.com/user-attachments/assets/371b34ef-775a-4d0b-88ed-ed8a702841ea" />

------------------------------------------------------------------------

## 1.1 用考试来理解

假设：

``` text
x:
What is the capital of France?

ỹ:
Paris

Dₓ:
Correct answer = Paris
```

evaluation metric：

``` text
μ(x, ỹ, Dₓ) = 1
```

因为答对了。

这里：

``` text
x   = 考题
ỹ   = 学生交的答案
Dₓ  = 标准答案 / 判分依据
μ   = 阅卷规则
```

这就是 automatic evaluation 最通用的框架。

------------------------------------------------------------------------

## 1.2 Dₓ 不一定只是一个"标准答案"

根据任务不同，Dₓ 可以完全不同：

  x             ỹ                Dₓ
  ------------- ---------------- ----------------
  word prefix   next word        true next word
  document      summary          gold summary
  question      answer           correct answer
  question      ranked answers   correct answer
  query         ranked items     relevant items
  query         ranked items     logged clicks

例如搜索系统：

``` text
x:
"best running shoes"

ỹ:
系统排出来的 10 个网页

Dₓ:
历史上用户真正点击过哪些网页
```

这时候 evaluation 就不是比较一句话，而是评价 **ranking 是否合理**。

------------------------------------------------------------------------

# 2. Language Model Evaluation 的四种任务

## 2.1 Classification

Classification： **输入一个东西，输出一个 label / decision。**

例如 sentiment：

``` text
Input: "The movie was amazing."

Output: Positive
```

或者 multiple choice：

``` text
Question: Capital of France?

A London
B Paris
C Tokyo
D Rome

Model prediction:
B
```

这种任务容易自动评价：Prediction == Gold Label

------------------------------------------------------------------------

## 2.2 Sequence Generation

LLM 更典型的是： **输出不是一个 label，而是一串 token / word / sentence / paragraph。**

例如：

``` text
Input: Summarize this article.

Model output: The Federal Reserve kept interest rates unchanged...
```

这就困难了。

因为可能有很多不同的正确表达：

``` text
Gold:
The dog is sleeping on the sofa.

Prediction A: The dog is sleeping on the sofa.

Prediction B: A dog is asleep on the couch.

Prediction C: There is a sleeping puppy on the couch.
```

B、C 可能语义都不错，却没有 exact match。所以 sequence generation 需要更复杂的 metric。

------------------------------------------------------------------------

## 2.3 Ranking

模型有时不是直接生成，而是： **把候选答案按照好坏排序。**

例如：

``` text
Question: Capital of France?

Candidates:
Paris
London
Tokyo
Berlin
```

模型可能给：

``` text
1. Paris
2. Berlin
3. London
4. Tokyo
```

evaluation 可以看：正确答案 Paris 被排在第几？

搜索、recommendation、retrieval 都属于典型 ranking problem。

甚至 next-token prediction 也可以理解成：

``` text
Vocabulary = 50,000 tokens

Model:
Paris      0.40
London     0.15
France     0.10
banana     0.0001
...
```

本质上模型给整个 vocabulary 排了一个概率顺序。

------------------------------------------------------------------------

## 2.4 Composite Task Evaluation

现实里不会只问: 模型会不会做一道数学题？

而会测：

``` text
Math
Coding
Reasoning
QA
Safety
Summarization
...
```

然后把多个 task 的结果组合起来。

这就是 **Composite Evaluation = 多项考试综合成绩。**

------------------------------------------------------------------------

# 3. Sequence Generation 的基本符号

课程使用：

$$
y = \text{target / ground truth}
$$

$$
\tilde{y} = \text{model prediction}
$$

例如：

``` text
y: The cat is sitting on the mat.

ỹ: The cat is sleeping on the mat.
```

记忆：

``` text
y  = 老师给的参考答案
ỹ  = 模型交上来的答案
```

论文之间 notation 可能不同，所以重点是理解角色，不要死记字母。

------------------------------------------------------------------------

# 4. Perplexity：模型看到真实文本时有多"惊讶"？

Perplexity 可以大白话理解为： **给模型看一段真实文本，问它：这句话是不是你认为很自然、很可能出现的语言？**

如果模型给真实 token 很高 probability：

``` text
PPL 低
→ 不惊讶
→ 模型觉得这段语言很自然
```

如果真实 token 经常是模型没想到的：

``` text
PPL 高
→ 很惊讶
→ 模型预测真实语言的能力较差
```

------------------------------------------------------------------------

## 4.1 一个极简例子

Prefix：I drink coffee every ___

真实下一个词：morning

Model A：

``` text
morning  0.70
night    0.10
car      0.001
```

Model B：

``` text
morning  0.02
banana   0.40
car      0.20
```

看到真实答案 `morning`：

``` text
Model A: "Oh，我本来就觉得 morning 很可能。"

Model B: "啊？居然是 morning？"
```

所以 A 对真实文本的 perplexity 更低。

------------------------------------------------------------------------

# 5. 为什么 Perplexity 比 Exact Match 更宽松？

假设真实 next word：dog

模型概率：

``` text
puppy  0.35
dog    0.34
cat    0.10
```

最后模型如果选：puppy

Exact Match：

``` text
puppy != dog
→ 0 分
```

但 perplexity 看的是：**你给真实 token `dog` 多大的 probability？**

模型其实给：P(dog) = 0.34 并不低。

所以 perplexity 能看出：虽然最终没选中 dog，但模型其实知道 dog 是非常合理的答案。

这就是课件所谓：**relaxation of exact match**

------------------------------------------------------------------------

# 6. Perplexity 最常见用途：Training 中的 Intrinsic Evaluation

训练 LLM 时最典型：

``` text
Training step 1K   → Validation PPL = 500
Training step 10K  → Validation PPL = 200
Training step 50K  → Validation PPL = 80
Training step 100K → Validation PPL = 45
```

通常希望：Validation Perplexity ↓

说明模型越来越会预测 held-out human language。

这就是 **intrinsic evaluation**：

> 我不是直接测 ChatGPT 最终帮助用户多少，而是在测 language model
> 本身对语言 distribution 的建模能力。

这和你前面训练 GPT-tiny 时计算 validation perplexity 是同一个概念。

------------------------------------------------------------------------

# 7. Perplexity 也可以用于系统层面的判断

课程给了一个有意思的例子：email filtering。

假设邮件：

### A：正常人类邮件

``` text
Hi John, I'll send you the report tomorrow morning.
```

可能：PPL = 正常范围

### B：高度模板化

``` text
Buy now! Buy now! Buy now! Buy now!
```

可能非常 predictable：PPL 极低

### C：乱码

``` text
table banana zxq airplane 829 cat therefore
```

模型完全预测不到：PPL 极高

所以：

``` text
too low  → 可能非常 templated
normal   → 可能更像自然语言
too high → 可能 gibberish / unusual text
```

注意：**低 perplexity 不等于"内容质量一定高"。**

它只是说明： **模型觉得这串 token 很 predictable。**

------------------------------------------------------------------------

# 8. 为什么机器生成文本有时 Perplexity 更低？

如果 generation 使用低 entropy decoding，例如：

``` text
small top-k
low temperature
```

模型总是在挑：最高概率附近的 token

所以生成文本可能：

``` text
very predictable
→ high likelihood
→ low perplexity
```

而人类写作偶尔会选更意外、更丰富的表达。

因此 perplexity 有时能帮助检测 machine-generated text。

但它不是完美检测器。

------------------------------------------------------------------------

# 9. Perplexity 的局限

最重要的一句话： **Perplexity measures likelihood, not meaning.**

它主要问：这串 token 对模型来说有多 likely？

它没有直接问：

``` text
事实正确吗？
逻辑合理吗？
有帮助吗？
有创意吗？
安全吗？
```

所以：

``` text
Low PPL ≠ automatically high-quality answer
```

这和你前面 temperature 实验非常相关：

``` text
低 temperature
→ 反复选择高概率 token
→ generated sequence 可能 PPL 很低
→ 但输出可能非常 repetitive
```

所以不能简单地说： PPL 越低，generation quality 一定越好。

------------------------------------------------------------------------

# 10. Exact Match：最严格的老师

公式：

$$
\mu(y, \tilde{y}) = \mathbb{I}(y = \tilde{y})
$$

这里 (`\mathbb{I}`{=tex}) 是 indicator function：

``` text
完全一样 → 1
不完全一样 → 0
```

例如：

``` text
Gold:Paris

Prediction:Paris

Exact Match = 1
```

但：

``` text
Gold: Paris

Prediction: The answer is Paris.

Exact Match = 0
```

虽然人类觉得完全正确。

------------------------------------------------------------------------

# 11. Exact Match 的优缺点

优点： **High precision：如果 exact match = 1，通常很有把握答案是对的。**

缺点： **Low recall：metric = 0 不代表答案一定不好。**

例如：

``` text
Gold:42

Prediction:The answer is 42.
```

Exact Match 可能失败，但语义完全正确。

所以适合：

``` text
Question Answering
Numerical Reasoning
```

尤其答案有唯一、明确形式时。

------------------------------------------------------------------------

# 12. Word Error Rate (WER)：别要求完全一样，看看要改多少

Exact Match 太狠：一个词错 → 整句 0 分

WER 放松这个要求。

课件公式：

$$
WER = \frac{\delta(y, \tilde{y})}{|y|}
$$

其中：

``` text
δ(y, ỹ) = word edit distance

|y| = reference y 的词数
```

大白话： **把模型答案改成标准答案，最少需要改几个词？再除以标准答案长度。**

------------------------------------------------------------------------

# 13. Edit Distance 是什么？

通常允许三种操作：

``` text
Substitution = 换一个词
Deletion     = 删除一个词
Insertion    = 插入一个词
```

例如：

``` text
Gold:I love my dog

Prediction:I love dog
```

只需要插入：

``` text
my
```

Gold 有 4 个词：

``` text
WER = 1 / 4 = 0.25
```

------------------------------------------------------------------------

## 13.1 再举一个例子

Gold：

``` text
I like red apples
```

Prediction：

``` text
I love green apples
```

需要：

``` text
love  → like   substitution
green → red    substitution
```

两次 edit。

Gold 长度：

``` text
4
```

所以：

``` text
WER = 2 / 4 = 0.5
```

------------------------------------------------------------------------

# 14. WER 比 Exact Match 好在哪里？

Exact Match：

``` text
I like red apples
I love green apples

→ 不一样
→ 0
```

WER：

``` text
只错了 2 / 4
```

所以它提供了：

> **错误程度，而不仅仅是对 / 错。**

这就是课件说的：

> **relaxes exact match**

------------------------------------------------------------------------

# 15. WER 的问题

## 问题 1：所有 edit 权重一样

``` text
cat → dog
```

和：

``` text
cat → nuclear-reactor
```

在简单 edit distance 中都可能只是：

``` text
1 substitution
```

但语义差异显然不同。

------------------------------------------------------------------------

## 问题 2：不理解 synonym / semantic similarity

例如：

``` text
Gold:
The child is happy.

Prediction:
The kid is joyful.
```

人类：

``` text
意思几乎一样
```

WER：

``` text
child → kid
happy → joyful
```

会算错误。

所以 WER 仍然是：

> **surface-form metric，而不是 semantic metric。**

常见用途：

``` text
Speech Recognition
Machine Translation（历史/特定场景）
```

------------------------------------------------------------------------

# 16. BLEU：不要整句 exact match，比较 n-gram

BLEU 的核心思想：

> **不要求整句和 reference
> 一模一样，而是看生成文本里的小片段，有多少也出现在 reference 中。**

关键字：

``` text
n-gram
precision
clipping
geometric mean
```

------------------------------------------------------------------------

# 17. 什么是 n-gram？

句子：

``` text
The cat sat on the mat
```

### 1-gram

一个词一个单位：

``` text
The
cat
sat
on
the
mat
```

### 2-gram

连续两个词：

``` text
The cat
cat sat
sat on
on the
the mat
```

### 3-gram

连续三个词：

``` text
The cat sat
cat sat on
sat on the
on the mat
```

### 4-gram

连续四个：

``` text
The cat sat on
cat sat on the
sat on the mat
```

n 越大，越强调：

> **不只是词对，还要局部词序和 phrase 对。**

------------------------------------------------------------------------

# 18. BLEU 为什么需要 n-gram？

假设 reference：

``` text
The cat sat on the mat.
```

Prediction A：

``` text
The cat sat on the mat.
```

Prediction B：

``` text
mat the on sat cat The
```

如果只看有哪些单词：

``` text
两句话词几乎完全一样
```

但 B 明显是乱码。

加入 2-gram、3-gram、4-gram 后：

``` text
The cat
cat sat
sat on
on the
the mat
```

Prediction A 能 match 很多。

Prediction B 几乎 match 不到。

所以 n-gram 能部分捕捉：

``` text
local word order / phrase structure
```

------------------------------------------------------------------------

# 19. BLEU 为什么是 Precision 思维？

最简单理解：

> **我生成出来的东西，有多少能在 reference 里找到？**

即：

``` text
Generated n-grams
       ↓
有多少出现在 references？
```

所以课件总结：

> **BLEU measures precision.**

大白话：

> **你写出来的这些词，有多少是"有根据"的？**

------------------------------------------------------------------------

# 20. 为什么 BLEU 要做 Clipping？

这是 BLEU 很重要的设计。

课件例子中 model generation 类似：

``` text
He picked the He sphere off the the the floor.
```

如果简单数 word overlap：

``` text
He
the
the
the
...
```

模型可以疯狂重复高频词骗分。

例如 reference 只有：

``` text
the ... the
```

也就是最多出现两次 `the`。

Prediction 却出现：

``` text
the the the the
```

BLEU 不允许四个都算 match。

它最多给：

``` text
clipped count(the) = 2
```

因为 reference 最多只提供了两个。

大白话： **Reference 里有几个，你最多领几个积分。不能重复刷同一个词骗分。**

------------------------------------------------------------------------

# 21. Clipped 1-gram Precision 例子

假设 prediction 有 11 个词。

经过 clipping 后，有 7 个词能有效匹配 reference：

``` text
clipped matches = 7
generated words = 11
```

那么：

$$
p_1 = \frac{7}{11} \approx 0.64
$$

也就是：

``` text
1-gram precision = 64%
```

注意 denominator 是： **generated text 中的 n-grams 数量。**

所以它是 precision。

------------------------------------------------------------------------

# 22. BLEU 的基本计算流程

课程课件给出的思路：

``` text
1. Compute clipped 1-gram precision
2. Compute clipped 2-gram precision
3. Compute clipped 3-gram precision
4. Compute clipped 4-gram precision
5. Take geometric mean
```

例如：

``` text
p1 = 0.80
p2 = 0.60
p3 = 0.40
p4 = 0.20
```

不是简单 arithmetic mean，而是 geometric mean：

$$
BLEU \propto (p_1 p_2 p_3 p_4)^{1/4}
$$

直觉：**不能只靠单词 overlap 很高就拿高分；更长的 phrase 也得 reasonably match。**

注：标准 BLEU 实际实现通常还包含 **brevity penalty**，防止通过生成极短句子获得虚高precision；本页课件展示的公式重点是在 n-gram precision 的主体思想。

------------------------------------------------------------------------

# 23. 为什么用 Geometric Mean？

假设：

``` text
Model A:
1-gram 很好
2-gram 很差
3-gram 很差
4-gram 很差
```

如果简单平均，1-gram 可能把其他项"救回来"。

Geometric mean 对某一项特别低更敏感。

直觉： **BLEU 希望你不能只做到"词差不多"，还要让连续短语也像正常reference。**

------------------------------------------------------------------------

# 24. BLEU 可以有多个 Reference

这是 BLEU 的一个重要优势。

例如翻译：

Chinese：我今天很开心。

可能有很多合理英文：

``` text
I am very happy today.
I feel really happy today.
I'm having a great day.
```

如果只有一个 reference：

``` text
I am very happy today.
```

其他合理翻译可能被误伤。

BLEU 可以使用 multiple target sequences，让生成 n-gram 与多个 reference比较。

因此比 Exact Match 更适合 machine translation。

------------------------------------------------------------------------

# 25. BLEU 的优点

课件总结：

``` text
relaxes exact match
handles multiple target sequences
historically correlates with human preferences in MT
```

也就是：**不用一模一样；允许多个合理 reference；在 machine translation 等一些任务上，与人类判断存在有用的相关性。**

------------------------------------------------------------------------

# 26. BLEU 的最大缺点：不懂语义

例如：

Reference：

``` text
The child is happy.
```

Prediction：

``` text
The kid is joyful.
```

人类：

``` text
语义非常接近
```

BLEU：

``` text
child != kid
happy != joyful
```

很多 n-gram 不 match。

所以：**BLEU 看 lexical overlap，不真正理解 semantic similarity。**

这也是为什么课件强调：

> BLEU 与 human preference 的 correlation **在一些任务上比另一些任务更好**。

尤其不能因为 BLEU 在 machine translation 上有历史价值，就假设它对所有open-ended natural language generation 都同样可靠。

------------------------------------------------------------------------

# 27. ROUGE：把 BLEU 的问题反过来问

最核心区别：

``` text
BLEU → Precision
ROUGE → Recall
```

### BLEU 问：**我生成的内容里，有多少出现在 reference？**

### ROUGE 问： **Reference 里应该有的内容，我覆盖了多少？**

------------------------------------------------------------------------

# 28. 用考试小抄理解 BLEU vs ROUGE (Pecision vs Recall)

标准答案有 10 个关键点。

### Student A

只写了 2 个点，但这 2 个全对。

``` text
Precision = 2 / 2 = 100%
Recall    = 2 / 10 = 20%
```

大白话：

``` text
写出来的都对
但漏了很多
```

BLEU-style precision 会比较喜欢这种"少说但说对"的情况。

### Student B

写了 12 个点，其中 9 个是标准答案里的。

``` text
Precision = 9 / 12 = 75%
Recall    = 9 / 10 = 90%
```

大白话：

``` text
说得比较多
有一些废话
但标准答案的大部分内容都覆盖了
```

这就是 precision 和 recall 的根本区别。

可以把 Precision 和 Recall 理解成两个完全不同的检查角度：

Precision：我说出来的东西，有多少是对的？

Recall：正确答案里该说的东西，我说出来了多少？

假设标准答案里有 10 个正确知识点：

Ground Truth: A B C D E F G H I J

模型只回答了：Prediction：A B

而 A、B 都是正确的。那么：

$$ Precision = \frac{\text{正确预测的内容}}{\text{所有预测的内容}} = \frac{2}{2} = 100\% $$

因为模型只说了两个，但两个都对。而：$$ Recall = \frac{\text{正确预测的内容}}{\text{Ground Truth 中所有应该找到的内容}} = \frac{2}{10} = 20\% $$

所以这个模型属于：Precision 很高，但 Recall 很低：说得少，但说出来的都对；漏掉了很多应该说的。

BLEU 更偏 Precision：我生成出来的东西，有多少能在 reference 里面找到？

ROUGE 更偏 Recall：Reference 里面应该有的东西，我覆盖了多少？所以总结任务特别关心这个问题：标准摘要中的重要内容，你到底覆盖了多少？

------------------------------------------------------------------------

# 29. ROUGE-k 的公式怎么理解？

课件：

$$
\mu(y, \tilde{y}, k) = \frac{|G_k(y) \cap G_k(\tilde{y})|}{|G_k(y)|}
$$

其中：

``` text
G_k(y) = reference y 里的 k-grams

G_k(ỹ) = prediction 里的 k-grams
```

分子：

``` text
两边共同出现的 k-grams
```

分母：

``` text
reference 里总共有多少 k-grams
```

注意 denominator 在 **reference**。

所以是 recall：**标准答案里的东西，我找回了多少？**

------------------------------------------------------------------------

# 30. ROUGE-1 例子

Reference：

``` text
The cat sat on the mat
```

Prediction：

``` text
The cat slept
```

粗略按 unigram 看：

Reference：

``` text
The
cat
sat
on
the
mat
```

Prediction：

``` text
The
cat
slept
```

共同覆盖：

``` text
The
cat
```

所以 ROUGE-1 的直觉是：

``` text
reference 中的一部分词被 prediction 覆盖
```

重点不是具体预处理细节，而是：

``` text
denominator = reference → recall
```

# 31. ROUGE-2

ROUGE-2 看 bigram。

Reference：

``` text
The cat sat on the mat
```

Reference 2-grams：

``` text
The cat
cat sat
sat on
on the
the mat
```

Prediction：

``` text
The cat slept on the sofa
```

Prediction 2-grams：

``` text
The cat
cat slept
slept on
on the
the sofa
```

共同：

``` text
The cat
on the
```

所以 ROUGE-2 不只看单词出现，还要求两个连续词匹配。

# 32. ROUGE 为什么适合 Summarization？

假设 gold summary 包含三个重要信息：

``` text
1. Company revenue increased.
2. Costs increased.
3. Profit declined.
```

模型 summary 只写：

``` text
Company revenue increased.
```

这句话完全正确，但漏掉很多重要内容。

如果只看 precision：它写出来的几乎都对,可能分数不错。

但 summarization 很关心： **Gold summary 的重要内容有没有被覆盖？**

所以 recall 思维很自然。

这也是 ROUGE 历史上常用于 summarization，课件特别提到 multi-document summarization (MDS)。

------------------------------------------------------------------------

# 33. ROUGE 的优缺点

优点：

``` text
relaxes exact match
can correlate with human preferences in summarization settings
```

缺点和 BLEU 很像：

> **Semantically similar words may still be ignored.**

例如：

``` text
Reference:
The company increased revenue.

Prediction:
The firm's sales grew.
```

人类知道：

``` text
company ≈ firm
increased ≈ grew
revenue ≈ sales
```

传统 lexical-overlap ROUGE 不真正理解这些 semantic relationships。

------------------------------------------------------------------------

# 34. Exact Match → WER → BLEU / ROUGE：为什么像一条演化路线？

可以这样理解：

### Level 1 --- Exact Match

``` text
整句完全一样吗？
```

太严格。

### Level 2 --- WER

``` text
不一样没关系，看看差几个 edit。
```

更柔和。

### Level 3 --- BLEU / ROUGE

``` text
不要求整句一样，
看看局部 n-gram overlap。
```

进一步允许不同表达。

但这些传统 metrics 仍然主要基于：

``` text
surface form / lexical overlap
```

而不是深层语义理解。

# 36. 用同一个例子比较所有 metric

Reference：

``` text
The dog is sleeping on the couch.
```

Prediction：

``` text
The puppy is asleep on the sofa.
```

人类：两句话语义很接近。

### Exact Match

``` text
0
```

因为不是完全一样。

### WER

会认为：

``` text
dog → puppy
sleeping → asleep
couch → sofa
```

存在多个 edits。

### BLEU

部分词 / n-gram match，例如：

``` text
The
is
on the
```

但 synonyms 不会自动被视为相同。

### ROUGE

也能发现一部分 reference n-gram 被覆盖，但同样不懂：

``` text
dog ≈ puppy
couch ≈ sofa
```

### Perplexity

它问的是另一类问题：

> Prediction 或 reference 对 language model 来说是否 probable / natural？

所以它不是直接计算 prediction 和 reference 的 lexical overlap。

------------------------------------------------------------------------

# 37. 一个特别重要的区别：Perplexity 和 BLEU/ROUGE 在测不同东西

Perplexity：

``` text
Model probability distribution
        ↓
How likely is the sequence?
```

BLEU / ROUGE：

``` text
Generated text
        ↕
Reference text
        ↓
How much lexical n-gram overlap?
```

所以：

> **Perplexity 需要模型给 token probabilities；BLEU/ROUGE 主要需要 prediction + reference text。**

这也是为什么 PPL 非常适合训练期间 intrinsic evaluation，而 BLEU/ROUGE 更常用于已经生成出来的 sequence evaluation。

------------------------------------------------------------------------

# 38. 为什么没有一个 Metric 可以解决所有问题？

假设一个模型输出：

``` text
The company reported higher revenue but lower profit.
```

我们可能同时关心：

``` text
Fluency
Correctness
Coverage
Factuality
Helpfulness
Safety
Creativity
```

但：PPL主要看 likelihood；

BLEU / ROUGE主要看 lexical overlap；

Exact Match主要看字符串是否一致。

所以 **Metric 是 construct 的 operationalization，不是 construct 本身。**

这正好接上上一讲。

------------------------------------------------------------------------

# 39. 课程里最值得记住的 Mental Model

面对一个新的 evaluation task，不要先问：

> "Should I use BLEU or ROUGE?"

先问：

``` text
1. What is my construct?
   我真正想测什么？

2. What kind of task is this?
   Classification?
   Sequence generation?
   Ranking?

3. What information do I have?
   Gold label?
   Reference sequence?
   Multiple references?
   Model probabilities?
   Human clicks?

4. What behavior should the metric reward?
   Exact correctness?
   Low edit distance?
   Precision?
   Recall?
   Likelihood?

5. Does this metric correlate with
   what users/humans actually care about?
```

# 40. 面试 / 考试常见问题

## Q1. What are the common task types in language-model evaluation?

> **Common evaluation templates include classification, sequence
> generation, ranking, and composite evaluations that aggregate
> performance across multiple tasks.**

------------------------------------------------------------------------

## Q2. What is perplexity?

> **Perplexity measures how surprised a language model is by a sequence.
> Lower perplexity means the model assigns higher probability to the
> observed text and therefore predicts it better.**

但记得补一句：

> **Lower perplexity does not necessarily imply better semantic quality,
> factuality, or usefulness.**

------------------------------------------------------------------------

## Q3. Why is perplexity more flexible than exact match?

> **Perplexity evaluates the probability assigned to the target token
> rather than only whether it was the single selected prediction. A
> model can therefore receive credit for assigning high probability to a
> correct token even if another token was ranked slightly higher.**

------------------------------------------------------------------------

## Q4. What is Exact Match?

> **Exact Match returns 1 when the generated sequence exactly matches
> the reference and 0 otherwise. It has high precision but low recall
> because semantically valid alternative answers may receive zero.**

------------------------------------------------------------------------

## Q5. What is Word Error Rate?

> **WER measures the word-level edit distance between the prediction and
> reference, normalized by the reference length. It relaxes exact match
> but does not capture semantic similarity between different words.**

------------------------------------------------------------------------

## Q6. BLEU vs ROUGE?

最重要一句：

> **BLEU is primarily precision-oriented: how much of the generated
> n-grams appear in the references. ROUGE is primarily recall-oriented:
> how much of the reference content appears in the generation.**

记忆：

``` text
BLEU:
What I SAID → how much was supported?

ROUGE:
What I SHOULD SAY → how much did I cover?
```

------------------------------------------------------------------------

## Q7. Why does BLEU use clipped counts?

> **Clipping prevents a system from receiving extra credit by repeatedly
> generating a word more times than it appears in the reference.**

大白话：

> **防止模型靠 "the the the the" 刷 overlap 分数。**

------------------------------------------------------------------------

## Q8. Why use n-grams instead of only individual words?

> **Higher-order n-grams capture some local word order and phrase
> structure, so a sentence cannot receive a high score merely by
> containing the right words in an arbitrary order.**

------------------------------------------------------------------------

## Q9. What is a major limitation of BLEU and ROUGE?

> **They rely heavily on lexical overlap and may penalize semantically
> equivalent paraphrases that use different words.**

------------------------------------------------------------------------

> **Automatic evaluation 的本质，是根据任务输出形式选择一个可重复计算的
> metric：分类可以直接比 label；sequence generation 可以用 perplexity
> 看模型对真实文本的 likelihood，用 exact match 看完全一致，用 WER 看
> edit distance，用 BLEU 看生成内容的 n-gram precision，用 ROUGE 看
> reference 内容的 n-gram recall；但这些 metric 都只是对我们真正关心的
> construct 的近似，而不是"语言质量"本身。**
