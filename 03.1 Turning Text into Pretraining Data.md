# Turning Text into Pretraining Data
## 1. 这节课到底在讲什么？

训练语言模型之前，不能直接把 Wikipedia、书籍或网页文本扔给神经网络。

神经网络最终需要的是**数字 Tensor**。所以整体流程可以记成：

``` text
Raw Text
   ↓
Cleaning / Filtering
   ↓
Tokenization
   ↓
Token IDs
   ↓
Batching
   ↓
Tensor
   ↓
Neural Network / LLM Training
```

大白话：

> **把人能读的文字，变成 GPU 能高效处理的一批批数字。**

这节课假设我们生活在"perfect
world"里：数据已经比较干净、高质量，因此重点放在 **Tokenization + Batching**。

高质量文本来源的例子包括 Wikipedia、Project Gutenberg，以及人工整理的数据集。

------------------------------------------------------------------------

# 2. Tokenization：把文字翻译成模型认识的数字

## 核心概念

Tokenization 的最终目标：

<img width="1001" height="239" alt="image" src="https://github.com/user-attachments/assets/e3c2a56e-4304-4f29-9afe-15409a081449" />


每个 token 在 vocabulary 里都有一个整数 ID。

因此：

``` text
Text → Tokens → Token IDs
```

模型真正看到的不是 `"Steelers"`，而是类似：

``` text
580, 109027, 1313, ...
```

这些 ID 后面再通过 embedding table 变成向量。

------------------------------------------------------------------------

# 3. 最简单的办法：Word-level Tokenization

Word-level tokenizer 的想法非常直观：

> **一个单词 = 一个 token。**

例如：

``` text
I love machine learning
```

可能变成：

``` text
["I", "love", "machine", "learning"]
```

再映射成：

``` text
[17, 83, 1257, 931]
```

通常通过空格、标点符号和人工规则切词。

## 问题：Open Vocabulary Problem

语言中的单词几乎是无限的。

假设训练时 vocabulary 里有：

``` text
cat
dog
machine
learning
```

后来模型遇到：

``` text
ChatGPT
```

如果 vocabulary 里没有它，word-level tokenizer 只能：

``` text
ChatGPT → [UNK]
```

`UNK = Unknown Token`

更麻烦的是 typo：

``` text
learning
learnign
```

在人看来只是拼错了两个字母，但 word tokenizer
可能认为它是一个从未见过的新词：

``` text
learnign → [UNK]
```

有些语言还会把多个成分组合成很长的词，使这个问题更加严重。

------------------------------------------------------------------------

# 4. Character-level Tokenization：另一个极端

既然完整单词太多，那可以把每个字符都作为 token：

``` text
learning
↓
l e a r n i n g
```

这样 vocabulary 很小，也几乎不会出现未知英文单词。

但问题是 sequence 太长。

例如：

``` text
internationalization
```

word-level：

``` text
1 token
```

character-level：

``` text
20+ tokens
```

Transformer 处理的 sequence 越长，计算越贵。

因此我们希望找到一个中间方案。

------------------------------------------------------------------------

# 5. Subword Tokenization：现代 LLM 的核心思路

Subword 的思想是   **常见的词尽量保持完整，罕见的词拆成几个常见的小块。**

例如：

``` text
playing
```

可能是：

``` text
play + ing
```

一个很罕见的词：

``` text
unbelievability
```

可能被拆成：

``` text
un + believe + ability
```

所以它介于：Character-level ← Subword → Word-level之间。

## 为什么这样好？

### 高频词

经常出现：

``` text
the
and
machine
```

可以直接拥有自己的 token。

### 低频词

不值得给每个罕见词单独占 vocabulary：supercalifragilistic...就拆成多个 subword。

这样既：

-   控制 vocabulary size
-   又减少 `[UNK]`
-   sequence 也不会像 character-level 那么长

------------------------------------------------------------------------

# 6. BPE --- Byte Pair Encoding

BPE 是一种学习 subword vocabulary 的方法。

核心思想只有一句：

> **不断寻找训练数据里最常一起出现的相邻 token
> pair，然后把它们合并成一个新 token。**

------------------------------------------------------------------------

## 7. 用例子理解 BPE

假设 corpus 里有：

``` text
hug   × 10
pug   × 5
pun   × 12
bun   × 4
hugs  × 5
```

最开始 vocabulary 只有字符：

``` text
b, g, h, n, p, s, u
```

所以：

``` text
hug  → h u g
pug  → p u g
pun  → p u n
bun  → b u n
hugs → h u g s
```

### Iteration 1

统计所有相邻 pair：

``` text
(h,u)
(u,g)
(p,u)
(u,n)
...
```

假设：u + g 出现最多。

于是创建新 token：ug

Vocabulary：

``` text
b g h n p s u ug
```

重新 tokenize：

``` text
hug  → h ug
pug  → p ug
hugs → h ug s
```

### Iteration 2

继续统计。

假设：u + n 现在最常见。

合并：un

Vocabulary 增加：un

于是：

``` text
pun → p un
bun → b un
```

### Iteration 3

假设：h + ug最常见。

合并：hug

现在：

``` text
hug → hug
hugs → hug s
```

不断重复：

``` text
Find most frequent adjacent pair
        ↓
Merge it
        ↓
Add new token to vocabulary
        ↓
Retokenize
        ↓
Repeat
```

直到：

``` text
vocabulary size == target vocabulary size
```

------------------------------------------------------------------------

# 8. BPE 最值得记住的本质

BPE 本质上是在**学习哪些字符/子词组合值得成为一个独立 token**。

非常常见的东西：

``` text
the
ing
tion
hug
```

更容易经过多轮 merge 后形成较大的 token。

非常罕见的东西则继续被拆成小块。

所以：

> **Vocabulary 不是工程师手写出来的，而是从 corpus的统计规律里学出来的。**

------------------------------------------------------------------------

# 9. Vocabulary Size 是一个 Hyperparameter

BPE 不会无限 merge。

工程师会提前决定：

``` text
target_vocab_size = ...
```

这是一个 design choice / hyperparameter。

Vocabulary 太小：

``` text
单词被拆得很碎
→ sequence length 变长
→ Transformer 计算增加
```

Vocabulary 太大：

``` text
embedding table 变大
→ 很多低频 token 学得不好
→ 参数和内存增加
```

因此这是一个 tradeoff：

``` text
small vocab
    ↕
sequence length
    ↕
large vocab
```

------------------------------------------------------------------------

# 10. 为什么 Subword 特别适合神经网络？

课件强调了三个优点。

## ① Controlled vocabulary size

Vocabulary 大小可以人为控制。

## ② Frequent words kept whole

常见词可以逐渐 merge 成完整 token。

## ③ Rare words split into reusable pieces

罕见词被拆成 subword。

例如：

``` text
walking
talking
running
```

模型可能多次看到：ing，于是 `"ing"` 的 representation 可以从大量样本中学习。

这比给每个罕见完整单词一个几乎没训练过的 embedding 更有效。

------------------------------------------------------------------------

# 11. BPE 仍然有问题

## 问题 1：Character vocabulary 本身也可能不完整

假设最基础 vocabulary 只有：

``` text
A-Z
a-z
```

突然出现：

``` text
你好
```

连基础字符都不存在，还是没办法 tokenize。

### 解决：Byte-level BPE

不要以：character作为最小单位，而以：byte作为最小单位。

Unicode 文本最终都可以表示成 bytes。

所以：

> **Byte-level BPE 让 tokenizer 可以覆盖非常广泛的 Unicode
> 文本，而不需要事先把世界上所有字符列进 vocabulary。**

------------------------------------------------------------------------

## 问题 2：传统 BPE 往往先需要 initial word tokenization

经典流程可能先：

``` text
Corpus
↓
split into words
↓
BPE inside words
```

但"什么叫一个 word"并不总是简单。

英文：

``` text
I love Pittsburgh
```

按空格大致可行。

中文：

``` text
我今天去学校
```

没有天然空格。

代码：

``` text
foo.bar(x++)
```

也不能简单按空格理解。

因此实际 tokenizer 往往需要更聪明的 pre-tokenization / rule-based
splitting。

------------------------------------------------------------------------

## 问题 3：训练 BPE 也需要高效实现

朴素方法不断寻找最频繁 pair，可能很慢。

实际系统会使用：

``` text
frequency tables
caching
incremental updates
efficient data structures
```

避免每轮从头扫描、计算所有 pair。

------------------------------------------------------------------------

# 12. Tokenization 完成以后：为什么还需要 Batching？

现在我们已经有：

``` text
document → token IDs
```

例如：

``` text
"Pittsburgh, Pennsylvania"
→ [47, 1468, 26320, 11, 20355]
```

另一个 document：

``` text
"Fido the dog likes eating..."
→ [37, 5362, 279, 5679, ...]
```

问题来了：

> **每个 document 长度不一样，GPU 怎么一次并行计算？**

神经网络非常擅长处理规则的 Tensor，例如：

``` text
[batch_size, sequence_length]
```

而不是：

``` text
[5 tokens]
[12 tokens]
[4 tokens]
[873 tokens]
```

所以我们需要 batching。

------------------------------------------------------------------------

# 13. 一个容易混淆的概念：Batch Size 到底是什么？

传统 ML / Computer Vision 经常说：batch_size = number of examples

例如：batch_size = 32 images

因为图片通常已经 resize 成统一 shape。

但是语言模型麻烦在：

``` text
Document A = 100 tokens
Document B = 2,000 tokens
Document C = 50,000 tokens
```

如果只说：batch_size = 32 documents，实际计算量可能完全不同。

因此在 **LLM pretraining** 语境中，更重要的尺度通常是：**一个 optimization batch 一共包含多少 tokens。**

课件给出的例子包括：

``` text
LLaMA-1:   4M tokens
T5:        65,536 tokens
OLMo:      4.19M tokens
GPT-3 175B: 3.2M tokens
```

这里重点不是死记数字，而是理解：

> **LLM training 的 workload 更自然地用 token 数衡量，而不是 document 数。**

------------------------------------------------------------------------

# 14. Batching Option 1：一个 document 一个 sequence

假设固定 sequence length：

``` text
8 tokens
```

Document A：

``` text
[47, 1468, 26320, 11, 20355]
```

只有 5 tokens。

补齐：

``` text
[47, 1468, 26320, 11, 20355, PAD, PAD, PAD]
```

Document B 如果超过 8：

``` text
[37, 5362, 279, 5679, 13452, 12459, 39824, 12556, ...]
```

则需要截断或分成多个 sequence。

问题：

``` text
很多短 document
→ 大量 padding
→ GPU 在 PAD 上做无意义计算
```

非常浪费。

------------------------------------------------------------------------

# 15. Batching Option 2：Packing Documents

更高效的方法是： **把多个 documents 的 token stream 拼起来，再切成固定长度的 chunks。**

例如：

``` text
Doc A:
47 1468 26320 11 20355

Doc B:
37 5362 279 5679 ...
```

中间加入 document boundary / EOS token：

``` text
47 1468 26320 11 20355 EOS 37 5362 ...
```

然后按照：

``` text
sequence_length = 8
```

连续切：

``` text
Batch sequence 1:
[47,1468,26320,11,20355,EOS,37,5362]

Batch sequence 2:
[279,5679,13452,12459,39824,12556,76486,10054]
```

这样 padding 大幅减少。

核心思想：

``` text
Documents
   ↓
Tokenize
   ↓
Concatenate / Pack
   ↓
Split into fixed-length sequences
   ↓
Batch Tensor
```

------------------------------------------------------------------------

# 16. 为什么 batching 对 GPU 如此重要？

GPU 最喜欢：大量规则、相同 shape 的矩阵运算

例如：

``` text
input_ids.shape = [batch_size, seq_len]
```

假设：

``` text
batch_size = 32
seq_len = 256
```

则一次处理：

``` text
32 × 256 = 8192 tokens
```

Tensor：

``` text
[32, 256]
```

而不是让 GPU 一会处理 17 tokens，一会处理 8,921 tokens。

所以 batching 的本质不是"整理数据好看"，而是： **把不规则的自然语言数据，整理成 GPU 能高吞吐并行计算的规则 Tensor。**

------------------------------------------------------------------------

# 17. 和你训练 GPT-tiny 时的参数怎么对应？

你之前训练 decoder-only GPT 时用过类似：

``` yaml
batch_size: 32
seq_len: 256
```

在这种实现里，一个 step 的 token 数大约是：

``` text
tokens_per_step = batch_size × seq_len = 32 × 256 = 8192 tokens
```

如果还有：grad_accumulation_steps = 4

那么一次 optimizer update 的 effective token batch 大约：

``` text
32 × 256 × 4 = 32,768 tokens
```

如果再做多 GPU data parallel：

``` text
global_tokens_per_update
≈ batch_size_per_GPU
× seq_len
× num_GPUs
× grad_accumulation_steps
```

这就是为什么大型 LLM training 经常直接讨论：tokens per batch

而不仅仅说：batch size = 32

------------------------------------------------------------------------

# 18. Tokenization 和 Batching 要分清楚

这是很适合面试的一张脑图：

``` text
RAW TEXT
   │
   ├── Cleaning
   │     remove HTML / bad content / etc.
   │
   ├── Tokenization
   │     text → discrete tokens
   │
   ├── Vocabulary lookup
   │     token → integer ID
   │
   ├── Packing / Batching
   │     organize IDs into fixed-size sequences
   │
   ▼
Tensor [B, T]
   │
   ├── Embedding lookup
   ▼
Tensor [B, T, D]
   │
   ▼
Transformer
```

其中：

``` text
B = batch dimension
T = sequence length
D = embedding / hidden dimension
```

------------------------------------------------------------------------

# 19. 面试最值得记住的几个 Tradeoffs

## Word-level vs Character-level vs Subword

  ------------------------------------------------------------------------------
  方法                    优点                           缺点
  ----------------------- ------------------------------ -----------------------
  Word-level              sequence 短、直观              vocabulary
                                                         巨大、UNK/OOV

  Character-level         vocabulary 小、几乎无未知词    sequence 很长

  Subword                 两者折中、处理 rare words 好   tokenizer 本身更复杂

  Byte-level BPE          Unicode                        某些文本可能需要更多
                          覆盖强、基本避免无法编码字符   tokens
  ------------------------------------------------------------------------------

一句话：

> **Subword tokenization trades vocabulary size against sequence length.**

------------------------------------------------------------------------

# 20. BPE 面试版答案

如果面试官问：

### "How does BPE work?"

可以回答：

> BPE starts from a small base vocabulary and repeatedly finds the most
> frequent adjacent token pair in the training corpus, merges that pair
> into a new token, and adds it to the vocabulary. The process continues
> until the target vocabulary size is reached. This allows frequent
> patterns or words to become single tokens while rare words remain
> decomposed into reusable subwords.

大白话：

> **从最小积木开始，谁俩天天黏在一起，就把它们焊成一块新积木。不断重复，最后常见词变成大积木，罕见词还是由小积木拼出来。**

------------------------------------------------------------------------

# 21. Batching 面试版答案

### "Why is batching necessary in LLM pretraining?"

> Batching converts variable-length tokenized text into regular tensors
> that GPUs can process efficiently in parallel. In language-model
> pretraining, batch size is often discussed in terms of the total
> number of tokens processed per optimization step rather than simply
> the number of documents, because documents have highly variable
> lengths.

一句话：

> **Batching = 把长短不一的文本整理成 GPU 能批量做矩阵运算的规则Tensor。**

------------------------------------------------------------------------

# 22. 本节最终总结

整个 `Turning Text into Pretraining Data` 可以压缩成：

``` text
Raw high-quality text
        ↓
Cleaning + Filtering
        ↓
Tokenizer
        ↓
Subword / Byte-level BPE
        ↓
Token IDs
        ↓
Packing
        ↓
Fixed-length sequences
        ↓
Batch Tensor [B, T]
        ↓
Embedding [B, T, D]
        ↓
Transformer Pretraining
```

真正需要掌握的三个核心：

1.  **Tokenization**：把文本变成离散 token，再映射成 integer IDs。
2.  **Subword/BPE**：在 vocabulary size 和 sequence length
    之间做折中；高频模式合并，罕见词拆开。
3.  **Batching**：把 variable-length 文本组织成规则 Tensor，让 GPU
    高效并行训练。

> **最重要的一句话：LLM数据预处理的本质，是把"不规则的人类文本"转换成"规则、高效、GPU-friendly的 token tensors"。**
