# 5.1--5.3: From Full Fine-Tuning to Instruction-Following Models

## 1. 整章主线

``` text
每个任务从头训练一个模型
        ↓
Pretraining + task-specific full fine-tuning
        ↓
Multi-task learning
        ↓
Instruction tuning
        ↓
Conversational + instruction-following model
```

最重要的思想变化：

**以前：任务决定模型。**

``` text
Translation → Model A
Summarization → Model B
QA → Model C
Sentiment → Model D
```

**后来：一个通用模型，通过 instruction 判断当前要做什么。**

------------------------------------------------------------------------

## 2. 早期：每个任务从 scratch 训练

早期 NLP 的典型做法：

``` text
想做 English → French
→ 找 translation dataset
→ 从头训练 translation model

想做 summarization
→ 找 summarization dataset
→ 再训练一个新模型
```

也就是 **one task → one dataset → one model**。

问题：不同模型都要重复学习 grammar、syntax、word meaning、sentence
structure 等基础语言知识，成本很高。

------------------------------------------------------------------------

## 3. Pretraining + Full Fine-Tuning

BERT、T5 等带来了 paradigm shift：

``` text
大量通用文本
→ Pretraining
→ General pretrained LM
→ 针对具体任务 fine-tune
```

大白话：**先让模型"读很多书"，获得通用语言能力，再教它具体工作。**

Pretraining
学习语言结构、语法、词义、常见语言模式以及部分世界知识。之后，只需要相对少量
task-specific data 就可以适配
QA、summarization、classification、generation 等任务。

如果任务需要特殊 domain knowledge，例如 medical notes
summarization，也可以进一步做 domain-specific fine-tuning。

------------------------------------------------------------------------

## 4. 什么是 Full Fine-Tuning？

Full model fine-tuning：

> 拿 pretrained model 在新任务数据上继续训练，并更新整个模型的参数。

``` text
Pretrained T5
→ Summarization data
→ 所有参数更新
→ T5-Summarization

Pretrained T5
→ Translation data
→ 所有参数更新
→ T5-Translation
```

所以一个 base model 最后可能产生很多完整的 task-specific copies。

------------------------------------------------------------------------

## 5. Full Fine-Tuning 的三个主要问题

### 5.1 每个任务都要重新训练

100 个 tasks 可能意味着很多次独立 fine-tuning，compute 成本高。

### 5.2 每个任务都要保存一整个模型

模型从 millions of parameters 增长到 billions 后，为
QA、summary、translation 等任务分别保存和部署完整模型变得很昂贵。

理想目标是：

``` text
ONE MODEL
→ QA
→ Summary
→ Translation
→ Classification
→ ...
```

### 5.3 小数据集容易 overfit

``` text
Huge model + Tiny task dataset → 容易 overfit
```

模型可能过度适应小 dataset，并损害 pretraining 学到的 general
knowledge。调整 learning rate 等 hyperparameters
可以缓解，但问题仍然存在。

------------------------------------------------------------------------

## 6. Full Fine-Tuning 的替代方向

课程接下来介绍：

-   In-context learning
-   Parameter-efficient tuning
-   Multi-task learning
-   Instruction tuning

本节的核心发展线是：

``` text
Multi-task learning
→ Instruction tuning
→ Conversational instruction-following models
```



# LLM Adaptation Methods Comparison

| Method | 核心思想 | Update Model Weights? | Task Examples 放在哪里？ | 每个 Task 需要单独模型吗？ | 最大优点 | 主要缺点 |
|---|---|---:|---|---|---|---|
| **Full Fine-Tuning** | 在 task-specific data 上继续训练整个 pretrained model | ✅ Yes，更新全部参数 | Training dataset | ✅ 通常需要每个 task 保存一份完整模型 | Adaptation 能力强，通常 performance 好 | 训练、存储、部署成本高；小数据容易 overfit / forgetting |
| **In-Context Learning (ICL)** | 不训练模型，把 instruction / examples 直接放进 prompt，让模型在 inference 时理解任务 | ❌ No | Prompt / context window | ❌ No | 完全不需要训练；换任务非常灵活 | Prompt-sensitive；占 context window；每次 inference 都要重新处理 examples |
| **Parameter-Efficient Tuning (PEFT)** | 冻结大部分 pretrained weights，只训练很少的参数 | ⚠️ Yes，但只更新/增加少量参数 | Training dataset | ❌ 不需要完整模型 copy，只保存小量 task-specific parameters | 比 full fine-tuning 便宜很多；方便存储和切换多个 task | 某些任务可能不如 full fine-tuning；仍然需要 training |
| **Multi-Task Learning** | 一个模型同时在多个 tasks 上训练，让同一套参数学会多种任务 | ✅ Yes | Multiple task datasets | ❌ 一个模型处理多个 tasks | 参数共享；减少 one-model-per-task；可以利用任务间共享知识 | 不同 task 数据量不平衡；任务之间可能互相干扰；需要告诉模型当前是什么 task |
| **Instruction Tuning** | 用大量 `(natural-language instruction → response)` examples 训练模型，让它学会“理解指令并完成任务” | ✅ Yes（可以 Full FT，也可以 PEFT） | Instruction-response training data | ❌ 一个模型希望 generalize 到很多甚至 unseen tasks | 提升 instruction following 和 zero-shot generalization | 高质量、多样化 instruction data 很重要；训练数据设计会强烈影响模型行为 |

## 最重要的区别

```text
Full Fine-Tuning
= HOW to update parameters
→ 更新全部参数

PEFT
= HOW to update parameters
→ 只更新很少参数

Instruction Tuning
= WHAT to train on
→ natural-language instructions + responses

Multi-Task Learning
= WHAT task structure to train on
→ many tasks together

In-Context Learning
= 不训练
→ task information 放进 prompt

------------------------------------------------------------------------

## 替代方向 1. Multi-task Learning：一个模型同时学很多任务

定义：

> **Multi-task learning = train one neural network to perform multiple tasks.**

T5 同时在多个 NLP tasks 的 mixture 上训练，例如 summarization、translation、QA、classification 等。

但马上出现一个问题：

> 一个模型会很多任务，它怎么知道这次应该做哪个？

### T5：用 Task Prefix 告诉模型做什么

T5 在 input 前面加 task prefix/tag：

``` text
summarize: Daniel Radcliffe gains access ...
```

或者：

``` text
translate en to fr: The legislative assembly ...
```

所以：

``` text
TASK TAG + INPUT
→ ONE MODEL
→ appropriate output
```

### T5 Task Tags 的 limitation

固定 tag 可以告诉模型
task，但它们不充分训练模型理解各种自然语言任务描述。

真实用户不会永远说：

``` text
summarize:
```

而可能说：

``` text
Could you give me the main points?
Write an outline.
Make this shorter.
```

这推动了 **instruction tuning**。


### T0：把 Task Tag 变成 Natural Language Instruction

T0 的核心 idea：

> 不只用机器式 tag，而是直接用自然语言告诉模型做什么。

T5 风格：

``` text
summarize: <article>
```

T0 风格：

``` text
Can you write an outline of the following article in a few points?
<article>
```

同一个 task 可以对应多种 instruction。

#### 为什么 Natural Language Instructions 更强？

真实用户可以用很多方式表达同一个需求：

``` text
Summarize this.
Give me the main points.
Can you make this shorter?
Write an outline.
What are the key ideas?
```

目标是让模型从：

``` text
看到固定 tag → 做固定 task
```

进化为：

``` text
理解 instruction
→ 判断用户希望做什么
→ 执行任务
```


#### P3：就是T0 使用的Tasks + Instruction Templates 

T0 使用的 tasks + instruction templates collection 称为 **P3**。

同一个原始 example 可以包装成不同 prompts。这样训练的目标是：

``` text
Same underlying task
→ many natural-language instructions
→ model learns robustness to wording
```

### Generalization to Unseen Instructions

Instruction tuning 希望模型即使没见过 inference 时的 exact wording，也能理解任务。

训练时：

``` text
Summarize this text:
```

测试时：

``` text
Please, my dearest AI, could you help me summarize this text?
```

模型仍应该识别：

``` text
task = summarization
```

这叫 **generalization to unseen instruction templates**。

更进一步，T0 还研究对 held-out / unseen tasks 的 zero-shot generalization：模型在许多 instruction-described tasks
上训练后，希望能根据 instruction 处理训练时未直接使用的 evaluation tasks。

------------------------------------------------------------------------

### FLAN：扩大 Instruction Tuning

FLAN 延续同一个思想：

``` text
Many datasets
+ Many task categories
+ Multiple instruction templates
→ Instruction tuning
```

课程 slides 中包括 Natural Language
Inference、Commonsense、Sentiment、Paraphrase、Closed-book QA、Reading
comprehension、Coreference、Summarization、Translation、Structure-to-text
等 task clusters。

重点不是背 dataset 名字，而是：

> **覆盖的 tasks 和 instructions 越多样，模型越有机会学习"根据instruction 做任务"这种 general skill。**

------------------------------------------------------------------------

### 为什么一个 Task 要有很多 Instruction Templates？

例如 NLI 可以写成：

``` text
Based on the paragraph above, can we conclude that <hypothesis>?
```

也可以：

``` text
Can we infer the following?
```

也可以：

``` text
Determine whether the hypothesis can be inferred from the premise.
```

如果永远只训练一种 wording，模型可能学的是某个固定 phrase 与 task 的映射，而不是 instruction 的语义。

因此需要：

``` text
Task diversity × Instruction wording diversity
```

------------------------------------------------------------------------

### Multitask Learning Challenge 1：不同 Task 数据量不平衡

例如：

``` text
English → French       10M examples
English → German        8M examples
Japanese → French      100K examples
Chinese → Quechua       10K examples
```

如果简单把所有 examples 混在一起随机 sample，high-resource tasks 会支配
training，low-resource tasks 容易被淹没。

所以需要设计 **mixing strategy**。T5 探索了 equal
mixing、examples-proportional mixing、temperature-scaled mixing 等策略。

核心问题：

> 每个 task 应该以多大的概率被 sample，才能让模型学得比较均衡？

### Challenge 2：Instruction Diversity

如果 training 只出现：

``` text
Summarize this text:
```

用户说：

``` text
Give me the three most important points.
```

模型未必能很好 generalize。

因此 instruction-tuning dataset 要同时有：

``` text
很多 task
+
每个 task 的很多种自然语言表达
```

### Challenge 3：什么叫"完成任务"？

传统 NLP benchmark 通常希望输出容易评分：

``` text
positive / negative
entailment / not entailment
```

但真实用户可能希望：

``` text
解释原因
用大白话
给例子
简洁回答
```

所以现代模型需要考虑的不只是：

``` text
correct label
```

还包括：

``` text
correct
+ useful
+ conversational
+ relevant
+ safe
+ follows user's intent
```

这自然引向 alignment：**我们到底希望 language model 学会什么behavior？**

------------------------------------------------------------------------

## 另一条研究线：Dialog Systems

另一批研究者在研究 neural language models 如何进行 multi-turn conversation：

``` text
previous utterances
→ model predicts next utterance
→ conversational response
```

早期数据包括 movie subtitles、IRC logs 等。

这里的核心目标不是某个 benchmark accuracy，而是模型能不能自然地和用户聊天。

------------------------------------------------------------------------

## 为什么 Dialog Systems 和 Multi-task Learning 最终合流？

Multi-task learning 想要：

``` text
ONE MODEL
→ translation
→ QA
→ summarization
→ classification
→ ...
```

Dialog systems 想要：

``` text
ONE MODEL
→ understand user
→ maintain conversation
→ respond naturally
```

两者结合：

``` text
User uses natural language
→ describes what they want
→ model understands instruction
→ performs requested task
→ responds naturally
```

这就是现代 conversational instruction-following LM 的核心形态。


### LaMDA：Dialog / Alignment 方向的例子

课程把 LaMDA 作为 dialog-system 方向的重要例子。

它首先是 decoder-only language model，进行 next-token prediction，并在大量 documents 和 dialogs 上训练。

但目标不只是生成 plausible continuation，还希望 chatbot 的回答具有：

-   sensible
-   specific
-   interesting
-   factual
-   safe

### LaMDA fine-tuning 流程（课程 slides）

① 原始 LaMDA
   ↓
② Judge / Discriminator：专门判断“这个回答好不好”
   ↓
③ 改进后的 LaMDA：专门生成更好的回答

1.  让 crowdworkers 和 LaMDA 进行 multi-turn conversations。 Crowdworkers 就是找来做数据标注的人。
他们真的和原始 LaMDA 聊很多轮：Human: What do you like to do? LaMDA: I like reading books. Human: What kind of books? LaMDA: I like science fiction.
为什么先聊天？因为我们首先需要收集：LaMDA 在真实 conversation 中到底会产生什么样的回答。里面肯定有好的，也有差的。

2.  让另一批 crowdworkers 从 sensible、specific、interesting、safe 等维度评价 conversations。再找人类给这些回答“打分”，换另一批 crowdworkers，当老师/裁判。

3.  Fine-tune pre-trained LaMDA 来预测这些 candidate response ratings，形成 discriminators。用这些“人类评分”训练一个 AI 裁判，
现在问题来了：Internet / pretraining data 有几百万甚至几十亿条，我总不能让人类一条条看吧？太贵了。
所以 Google 做了一件聪明的事情：Human ratings ->  Fine-tune model ->  让模型学会模仿人类的判断, 于是得到 discriminator。
你可以把 discriminator 理解成：AI 质检员。
它不是主要负责跟用户聊天，而是负责：

输入：candidate response

输出：
Sensible?    0.95
Specific?    0.91
Interesting? 0.87
Safe?        0.99

所以 Step 3 的核心是：先让人类教会一个 AI“什么叫好回答”。

4.  用 discriminator models 给大量 pretraining utterances 打标签。现在让 AI 裁判去大规模筛数据，
有了 AI 质检员以后，就不用让人类看几百万条数据了。让 discriminator 去看大量 utterances。

5.  用被判断为 sensible、specific、interesting、safe 的 utterances 再fine-tune LaMDA。用筛出来的“好回答”重新教育 LaMDA
现在手里有了一大批：AI judge 认为：✓ sensible ✓ specific ✓ interesting ✓ safe的 utterances。

然后：这些 high-quality examples
        ↓
继续 fine-tune LaMDA
        ↓
LaMDA 更倾向生成这样的回答
   
6.  再使用由 crowdworkers 修改、包含 web-search sourced facts 的conversations 进行进一步 fine-tuning，使模型学习使用外部信息。最后再教 LaMDA：“不知道的时候可以去外面找资料”
前 5 步主要解决：怎么让 LaMDA 说话更 sensible / specific / interesting / safe？
但还有一个大问题：LaMDA 自己脑子里的知识，可能过时，可能不知道，可能记错，所以课程 slides 里又加入了一批由 crowdworkers 修改过的 conversations，而且这些回答里包含 来自 web search 的事实。

## 从 Next-Token Prediction 到 Alignment

Pretraining objective：

``` text
Predict next token.
```

但：next-token prediction ≠ helpful ≠ factual ≠ safe ≠ follow user intent

因此发展方向逐渐变成：

``` text
Pretraining
“学会语言”
        ↓
Instruction / dialog tuning
“学会听懂要求、完成任务”
        ↓
Alignment-related tuning
“按照希望的行为方式回答”
```

课程指出 LaMDA 是较早体现这类 alignment 思路的例子之一。

------------------------------------------------------------------------

## Instruction-Tuning Datasets 为什么很重要？

不同 datasets 可以在这些方面不同：

-   examples 是 human-written、LLM-generated，还是 mixed
-   来自 traditional NLP datasets，还是专门为 instruction following 创建
-   包含多少 languages
-   target response 的长度和风格
-   instruction 类型有多 diverse

因此：

``` text
Same pretrained model + different instruction-tuning data → different behavior
```

选择 open-source instruction-following model 时，不应该只看 model size，也应该看它是用什么 instruction data tuning 的。

## 26. Full Fine-Tuning vs Instruction Tuning：不要混淆

这两个概念不是反义词。

**Full fine-tuning** 描述：

> 更新多少 parameters / 如何更新 parameters？

**Instruction tuning** 描述：

> 用什么样的 training examples 来教模型？

所以完全可以使用 full parameter updates 做 instruction
tuning，也可以使用 parameter-efficient methods 做 instruction tuning。

``` text
Full fine-tuning / PEFT
→ HOW parameters are updated

Instruction tuning
→ WHAT kind of training examples are used
```

## 27. 最终大白话总结

### 第一代

``` text
我要翻译 → 训练一个翻译模型
我要总结 → 再训练一个总结模型
```

问题：太浪费。

### 第二代

``` text
先训练一个通用 pretrained model
→ 每个任务再 fine-tune
```

好很多，但仍然产生很多 task-specific models。

### 第三代：Multi-task Learning

``` text
一个 model 同时学：
translation
summarization
QA
classification
...
```

通过 task prefix 告诉模型当前做什么。

### 第四代：Instruction Tuning

不用固定机器 tag，而用自然语言：

``` text
Summarize this article.
Translate this into French.
Does this paragraph imply the following statement?
```

再与 dialog-system 思路结合：

``` text
用户自然聊天
+
用户用自然语言提出各种任务
+
模型理解并执行
+
自然回答
```

最终逐渐形成现代 **general-purpose conversational instruction-following
language model**。

# One-Page Cheat Sheet

``` text
FROM SPECIALISTS → GENERAL ASSISTANT

1. Train from scratch
   One task → one model
   Problem: expensive + duplicate learning

2. Pretraining + fine-tuning
   General LM → task-specific model
   Less task data needed
   BUT:
   - repeated fine-tuning cost
   - many full model copies
   - small datasets → overfitting

3. Multi-task learning
   One model → many tasks
   Need to specify which task
   T5: task prefixes

4. Instruction tuning
   Natural-language instructions instead of rigid tags
   T0 / P3 / FLAN-style approaches
   Many tasks + many instruction templates
   Goal: generalize to new wording and tasks

5. Dialog systems merge with multitask learning
   Understand conversation
   +
   perform many tasks
   ↓
   conversational instruction-following models
```

### Three challenges to remember

``` text
1. DATA MIXTURE
High-resource tasks can dominate low-resource tasks.

2. INSTRUCTION GENERALIZATION
The model should understand many ways of asking for the same thing.

3. WHAT COUNTS AS GOOD BEHAVIOR?
Benchmark labels are easy to score;
real users want useful, natural, factual, safe responses.
```

> **Core takeaway:** Modern instruction-following LMs emerged from
> moving away from "one task, one model" toward a single pretrained
> model that learns many tasks and uses natural-language instructions
> and conversation to determine what the user wants it to do.
