# Homework 5 --- Q2.1。Common Crawl Data Processing Pipeline

## 0. 这道题到底在讲什么？

一句话：

> **你要亲手做一次"把互联网网页变成 LLM
> 可以训练的文本数据"的最前面一步。**

你平时看到的语言模型训练数据，不是直接把网页 HTML
扔给模型。真实流程更像：

``` text
Internet webpages
      ↓
Common Crawl
      ↓
WARC: raw HTTP responses / raw HTML
      ↓
HTML → plain text
      ↓
cleaning
      ↓
PII masking
      ↓
quality filtering
      ↓
clean training corpus
      ↓
tokenization
      ↓
LLM pretraining
```

这道 Q2.1 主要让你完成：

``` text
WARC raw HTML
      ↓
html_to_text()
      ↓
Plain Text
```

同时观察 Common Crawl 官方生成的 **WET** 文件，比较你自己的 HTML→text
extraction 与 Common Crawl 的 extraction。

# 1. 为什么课程让你做这个？

前面课程讲过：

``` text
Internet → Crawl → HTML → Scrape → Clean → Filter → Deduplicate → Tokenize → Pretrain
```

这次不是只背 pipeline，而是亲手实现其中一段。

**核心思想：LLM 的能力不只取决于 model
architecture，也高度取决于训练数据怎样从原始互联网加工出来。**

网页里可能有 HTML tags、JavaScript、CSS、navigation menus、ads、cookie
notices、spam、PII、重复内容和 layout
artifacts。真正想给语言模型的是其中有意义的自然语言。

所以 **data processing 本身就是 LLM training system 的重要组成部分**。

------------------------------------------------------------------------

# 2. Common Crawl 是什么？

作业把 Common Crawl 描述为一个公开的互联网索引/抓取数据源。很多
open-source language models 的 pretraining corpus 都直接或间接来自它。

课程给出两个例子：

``` text
Common Crawl → processing → C4 → T5
Common Crawl → processing → Dolma → OLMo
```

因此：

> **Common Crawl ≠ training-ready dataset。**

Common Crawl 更像原材料；C4、Dolma 等是经过
extraction、cleaning、filtering 等步骤之后得到的训练 corpus。

------------------------------------------------------------------------

# 3. WARC / WET / WAT 到底是什么？

## WARC --- Web ARChive

保存抓网页时得到的 HTTP responses，包括 raw HTML。

``` text
URL
 ↓
HTTP response
 ↓
raw HTML
```

所以 **WARC 最接近原始网页**，而且这道题要求你从 WARC 开始。

## WET --- WARC Encapsulated Text

WET 已经做过：

``` text
HTML → text extraction → plaintext
```

因此它相当于 Common Crawl 团队提供的一版 HTML-to-text 结果。作业让你
inspect WET，就是让你比较：

``` text
Your html_to_text()
vs.
Common Crawl's extraction
```

## WAT --- Web Archive Transformation

主要保存 request/page metadata。

最简单的口诀：

``` text
WARC = 网页原材料
WET  = 网页文字
WAT  = 网页 metadata
```

------------------------------------------------------------------------

# 4. 什么叫 Shard？

Common Crawl 太大，所以整个 crawl 被拆成成千上万个 slices/shards。

``` text
Whole Crawl
 ├── Shard 1
 ├── Shard 2
 ├── Shard 3
 └── ...
```

课程的 `download_data.sh` 下载的是 **2018 Common Crawl dump 的一个
shard**。

所以 Deliverable 1 问的：

> How many HTML pages are in this shard?

是让你统计这个小切片里的 pages，而不是整个 Common Crawl。

# 8. 为什么不是简单 Regex 删除 Tags？

你可能会想到：

``` python
re.sub(...)
```

但 HTML 有 nested tags、malformed
HTML、entities、comments、scripts/styles、tables 等复杂结构。

所以核心原则是：

> **HTML 应该由 HTML parser 解析，而不是简单把它当普通字符串。**

# 10. Deliverable 2：你的 html_to_text 怎么处理三种 HTML？

老师要求你观察三个 component。

## Headers

例如：

``` html
<h1>Michigan Fall Colors</h1>
<h2>Best Places</h2>
```

观察输出是保留换行、空格，还是直接连起来。

核心问题：

> tag 去掉以后，header 里的文字和结构如何被保留？

## Embedded Images

例如：

``` html
<img src="cat.jpg">
```

它没有普通正文，可能直接消失。

如果有：

``` html
<img src="cat.jpg" alt="A black cat sleeping">
```

则要观察你的具体 extraction library / implementation 是否保留 alt text。

**根据自己的实际输出回答，不要猜。**

## Tables

例如：

``` html
<table>
<tr><th>Name</th><th>Age</th></tr>
<tr><td>Alice</td><td>30</td></tr>
</table>
```

网页表达的是二维结构：

``` text
Name     Age
Alice    30
```

但 plain text 可能变成：

``` text
Name
Age
Alice
30
```

或者：

``` text
Name Age Alice 30
```

这说明 HTML→text 不只是"删 tags"，还涉及：

> **如何把视觉/二维网页结构 linearize 成模型看到的一维 token
> sequence。**

# 12. 怎么判断哪个版本更适合 LLM Training？

不要预设 "Common Crawl 一定更好"。

判断标准应该是：

``` text
retain meaningful semantic content
+
retain useful textual structure
+
remove HTML/JS/CSS noise
+
reduce boilerplate
+
avoid formatting artifacts
```

换句话说：

> **哪个版本让模型看到更多有意义的自然语言、更少网页特有的噪音？**

必须根据你实际 inspect 的 WET 和自己的输出决定。

------------------------------------------------------------------------

# 13. 为什么老师专门让你比较 WET？

因为现实里：

> **HTML → text 没有唯一正确答案。**

同一个网页，两个 extraction pipeline 可以产生不同的文本。

于是：

``` text
same raw Common Crawl
+
different preprocessing decisions
=
different pretraining dataset
```

这也是为什么：

``` text
Common Crawl → C4
```

和：

``` text
Common Crawl → Dolma
```

最终得到的训练数据并不相同。

------------------------------------------------------------------------

# 14. 这为什么对 LLM 很重要？

假设网页有：

``` text
1,000 words useful article
+
2,000 words/artifacts of navigation, ads, scripts, cookie text
```

如果 extraction 很差，你花昂贵 GPU compute 学到的大量 tokens
其实是垃圾网页结构。

所以：

> **Data cleaning 决定了昂贵的 training compute 到底在学习什么。**

# 15. 后面三个 TODO 在干什么？

虽然 Q2.1 当前重点是 `html_to_text()`，starter code 已经展示了后续
stages。

## `replace_pii()`

PII = Personally Identifiable Information。

概念上：

``` text
"My email is person@example.com"
↓
"My email is [EMAIL]"
```

目的：减少 privacy leakage。

## `clean_text()`

处理低质量 substrings、异常 formatting、无效文本等：

``` text
raw extracted text → cleaner text
```

## `heuristic_quality_filter()`

决定整篇 document：

``` text
KEEP or REJECT
```

这就是前面课程讲过的 heuristic/rule-based filtering。
