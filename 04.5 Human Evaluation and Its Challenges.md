# Human Evaluation and Its Challenges

## Learning Objectives
- Explain the primary purposes of human evaluation in assessing language models.
- Identify and evaluate the challenges associated with human evaluation.
- Assess the effectiveness of different evaluation frameworks.

## 1. 为什么还需要 Human Evaluation？

Automatic metrics（Perplexity、BLEU、ROUGE、BERTScore、MMLU Accuracy 等）通常更快、便宜、可扩展、容易重复。但很多真正关心的行为很难自动量化，例如：

- coherence
- creativity
- appropriateness
- harmfulness / bias
- real-world usefulness

核心原则： 如果 automatic evaluation 能可靠反映 desired behavior，通常优先使用它；如果目标属性复杂、主观或高度依赖 context，就需要 human judgment。

## 2. Human Evaluation 的三个主要目的

### 2.1 Measure Desired Behaviors
判断 generated text 是否表现出我们想要的行为，例如 natural、coherent、relevant、appropriate、safe。

这和 Construct vs Metric 有直接联系：真正关心的是 construct（例如“回答质量”），automatic metric 只是 proxy。如果 proxy 不可靠，可以让人直接评价。

### 2.2 Compare Models or Systems
比较 Model A 和 Model B 时，automatic metric 可能无法捕捉细微差异。Human evaluator 可以判断哪一个更 natural、coherent 或 useful。

### 2.3 Understand Utility in Larger Systems
有时我们关心的不是 LLM component 自己，而是它放进完整 system 后有没有实际价值，例如一个 Diplomacy language agent。

## 3. Intrinsic vs Extrinsic Evaluation

**Intrinsic Evaluation**：测 component 本身。

```text
Model → benchmark → component-level score
```

**Extrinsic Evaluation**：把 component 放进完整 system / real-world task，看整个系统最终表现。

```text
LLM → Agent → Real task → System effectiveness
```

记忆：

```text
Intrinsic = 零件本身怎么样？
Extrinsic = 装进整台机器以后好不好用？
```

Intrinsic performance 好，不一定保证 extrinsic system utility 好。

## 4. Example 1 — 5-Level Quality Rating

课程引用 Zhang et al. (2020) 的 generated-text quality framework。

<img width="830" height="477" alt="image" src="https://github.com/user-attachments/assets/218ae761-0a49-4efd-9bf9-de1010e5940b" />


### High Quality
完全 plausible、自然、符合 context，几乎和 human-written content 无法区分。

### Decent
总体自然合理，但可能有 minor contradiction 或 subtle oddity。

### Passable
第一眼似乎合理，仔细读会发现 off-topic、repetition 或明显 contradiction。

### Bad
不再像 coherent English sentence，可能有 broken grammar、重复或 web-data fragments。

### Terrible
基本是 gibberish / fragmented words，没有正常 semantic meaning。

这个 framework 测的是 overall generation quality，而不是 `prediction == ground truth`。

它可以综合评价：
- plausibility
- fluency
- coherence
- consistency
- meaningfulness

## 5. Rating Framework 的问题：Subjectivity

“Decent”和“Passable”的边界并不天然客观。

```text
Same output
→ Annotator A: Decent
→ Annotator B: Passable
```

不同 evaluator 可能因为 personal perspective 或对 criteria 的不同理解而给出不同判断。

## 6. Rating vs Comparison

**Absolute Rating** 问：

```text
How good is this response?
```

例如 High Quality / Decent / Passable / Bad / Terrible。

**Model/System Comparison** 则可以让 evaluator 比较多个 outputs，判断哪个 response 更好。

两者都是 human judgment，但 operationalization 不同。

## 8. 为什么 Safety 适合 Attribute-Specific Evaluation？

如果只得到：

```text
Overall quality = 2/5
```

不知道问题究竟是 grammar、irrelevance、harmfulness 还是 bias。

Attribute-specific framework 可以得到：

```text
Coherent: Yes
Relevant: Yes
Harmful: Yes
Stereotype: Yes
```

因此 feedback 更 specific、interpretable、actionable。

## 9. 两类 Framework 对比

| Framework | 核心问题 | Output | 更适合 |
|---|---|---|---|
| Quality Rating | 整体质量怎么样？ | Ordinal level | Fluency / plausibility / overall quality |
| Attribute-Specific | 有没有某个具体问题？ | Yes/No | Safety / bias / harmfulness |

没有一个 framework 对所有 construct 都最好。应该先定义：

```text
What behavior are we trying to measure?
```

再决定如何让 humans 判断。

## 10. Human Evaluation 的主要 Challenges

### Challenge 1 — Subjectivity
不同 annotators 可能因为个人观点、文化背景、criteria interpretation 不同而产生 disagreement。

### Challenge 2 — Contextual Limitations
很多 response 必须结合 conversation context 才能正确评价。信息不足时，annotator 很难做 informed judgment。

### Challenge 3 — Incomplete Categories
预定义 taxonomy 不可能覆盖所有潜在 bias / harmful content。Framework 本身会限制 evaluator 能“看见”的 failure modes。

### Challenge 4 — Annotator Expertise
Medical correctness、technical claims、subtle bias 等可能需要 domain expertise。Annotator 不理解 criteria 会产生 noisy、unreliable labels。

### Challenge 5 — Time / Cost / Scalability
Human evaluation 需要阅读、理解 context、做判断，有时还需要 multiple annotators，因此 expensive、slow、labor intensive、hard to scale。

## 11. Automatic vs Human Evaluation

```text
Automatic Evaluation

+ Fast
+ Cheap
+ Scalable
+ Reproducible

- May miss nuanced human qualities
```

```text
Human Evaluation

+ Flexible
+ Context-sensitive
+ Can assess complex/subjective behaviors
+ Can assess real-world utility

- Subjective
- Expensive
- Slow
- Hard to scale
- Depends on annotator quality
```

所以通常不是 Automatic **OR** Human，而是二者互补。

## 12. 正确的 Evaluation Design 顺序

不要先问：

```text
Which metric should I use?
```

应该先问：

```text
Step 1:
What behavior / construct do I care about?

        ↓

Step 2:
Can an automatic metric measure it reliably?

        ↓

Yes → Automatic evaluation may work

No / Partially
        ↓

Human Evaluation

        ↓

Step 3:
Which human framework operationalizes it best?

Rating?
Comparison?
Attribute-specific questions?
Real-world task?
```

核心原则：

> 先定义要测什么，再决定怎么测。

## 14. 怎么判断一个 Human Evaluation Framework 是否有效？

可以问：

1. **Does it measure the intended behavior?**
2. **Are the criteria clearly defined?**
3. **Is enough context provided?**
4. **Can annotators reliably apply the criteria?**
5. **Is the framework scalable?**
6. **Does the taxonomy cover important failure modes?**

## 15. Interview-Ready Answers

### Why do we need human evaluation for LLMs?
> **Human evaluation is important when the behaviors we care about are difficult to quantify automatically, such as coherence, creativity, appropriateness, harmfulness, or real-world usefulness. It is also useful for comparing systems and evaluating how a language model performs as part of a larger application.**

### What are the three main purposes?
> **Human evaluation is mainly used to measure desired behaviors, compare models or systems, and understand the utility of a model within a larger system.**

### Intrinsic vs extrinsic evaluation?
> **Intrinsic evaluation measures a model or component directly, while extrinsic evaluation measures how well the model contributes to performance in a larger real-world system or task.**

### Main challenges?
> **The main challenges include subjectivity between annotators, insufficient context, incomplete evaluation categories, differences in annotator expertise, and the high cost and time required to conduct evaluation at scale.**

### Why attribute-specific evaluation for safety?
> **Attribute-specific questions make the evaluation more interpretable and actionable by asking annotators to identify concrete behaviors such as harmful language, hate, stereotypes, or other forms of bias instead of collapsing everything into a single overall quality score.**

## 17. 一句话记忆

> **Human Evaluation 的价值在于直接评价 automatic metrics 很难捕捉的复杂行为，例如 coherence、appropriateness、safety 和 real-world utility；但人的判断本身也会受到 subjectivity、context、criteria、annotator expertise 和成本的限制，所以关键不是“human 一定比 automatic 好”，而是先定义要测的 construct，再选择最合适的 evaluation framework。**
