# 5.4.1--5.4.2 In-Context Learning（ICL）笔记

> **一句话主线：In-context learning
> 不重新训练模型、不更新参数，而是把"任务说明和例子"放进
> prompt，让模型在当前 context 里看懂这次要怎么做。**

## 1. 为什么会出现 In-Context Learning？

传统 fine-tuning：

``` text
Pretrained Model
→ task-specific dataset
→ training / backprop
→ update model weights
→ task-specific model
```

In-context learning（ICL）：

``` text
Pretrained LM
→ 不训练、不 backprop、不更新 weights
→ 把 instruction / examples 放进 prompt
→ inference
```

大白话：

> **Fine-tuning 是把任务"训练进参数"；ICL
> 是考试时把说明书和例题放在卷子前面，让模型现场照着做。**

------------------------------------------------------------------------

## 2. GPT-2 与 Emergent Abilities

课程引用 GPT-2 论文 *Language Models are Unsupervised Multitask
Learners*。核心观察是：大规模 language-model pretraining
后，模型开始表现出一些没有针对该任务显式监督训练的能力，例如：

-   question answering
-   machine translation
-   reading comprehension
-   summarization

课程 slides 还强调，这些表现会随着 model size 增长而增强。

### Emergence

课程定义：

> **Emergence:** quantitative changes in a system result in qualitative
> changes in behavior.

大白话：

``` text
模型规模等“量”发生变化
        ↓
模型开始出现以前没有/很弱的新行为
        ↓
qualitative behavioral change
```

### Emergent behaviors

课程定义为：

> abilities that larger models have and smaller models don't.

------------------------------------------------------------------------

## 3. 什么是 In-Context Learning？

课程定义：

> A language model "learns" how to do a task from a textual prompt
> containing a natural-language instruction, several exemplars of the
> task, or both.

这里 **"learns" 要加引号**，因为没有：

``` text
loss → backprop → gradient → update weights
```

而是：

``` text
Prompt contains task information
→ model conditions on that context
→ produces an appropriate continuation
```

所以：

> **ICL = learning from the prompt/context at inference time, without
> gradient updates.**

------------------------------------------------------------------------

## 4. Zero-Shot Learning

Zero-shot 是 ICL 的一种：

> **Prompt 中没有 task exemplars。**

例如 sentiment classification：

``` text
Review:
This restaurant was fantastic.

On a 1 to 4 star scale,
the reviewer would probably give this restaurant a:
```

模型可以比较 possible labels：

``` text
P("1" | prompt)
P("2" | prompt)
P("3" | prompt)
P("4" | prompt)
```

然后选择 likelihood 最大的 label。

核心：

``` text
0 exemplars → zero-shot
```

------------------------------------------------------------------------

## 5. Few-Shot Learning

Few-shot 也是 ICL，但 prompt 中先给几个 demonstrations：

``` text
Review: Terrible food.
Sentiment: Negative

Review: I loved this restaurant.
Sentiment: Positive

Review: The service was wonderful.
Sentiment:
```

前两个就是 **exemplars**。

模型从它们观察：

-   task 是什么
-   input/output format
-   labels 如何使用
-   task pattern

然后完成最后一个。

``` text
Zero-shot = instruction/prompt + 0 exemplars
Few-shot  = instruction/prompt + several exemplars
```

### 最容易混淆的点

Few-shot ICL **不是**拿几个 examples 做 gradient training。

``` text
examples 放进 prompt
→ inference
→ weights 不变
```

------------------------------------------------------------------------

## 6. Zero-Shot vs Few-Shot vs Fine-Tuning

  Method            Prompt 中有 examples？   更新 model weights？
  --------------- ------------------------ ----------------------
  Zero-shot ICL                         No                     No
  Few-shot ICL                         Yes                     No
  Fine-tuning        使用 training dataset                    Yes

一句话：

``` text
Fine-tuning → change the model
ICL         → change the context
```

------------------------------------------------------------------------

## 7. Verbalizer 是什么？

课程定义：

> **Verbalizer = the template we wrap an example in in order to perform
> the task.**

同一个 translation task 可以有不同 templates。

### Template A

``` text
The dog chased a squirrel at the park. = 那只狗在公园里追一只松鼠。
I was late for class. = 我上课迟到了。
The hippopotamus ate my homework. =
```

### Template B

``` text
Translate from English to Chinese.

The dog chased a squirrel at the park. = ...
The hippopotamus ate my homework. =
```

### Template C

``` text
Translate from English to Chinese.

English: The dog chased a squirrel at the park.
Chinese: ...

English: The hippopotamus ate my homework.
Chinese:
```

Task 相同，但包装 task 的方式不同，这些不同 templates 就是 verbalizers。

------------------------------------------------------------------------

## 8. Prompt Engineering

课程定义：

> **Prompt engineering:** trying many different prompts until you find
> one that works well for your task.

为什么需要它？

因为尤其是早期 few-shot ICL 很 brittle：

``` text
同一个 task
+ 只改 wording / formatting / order
→ performance 可能变化很大
```

所以会反复尝试 prompt、example order、labels 等。

------------------------------------------------------------------------

## 9. ICL 为什么不够 Robust？

课程列出 few-shot ICL 对以下变化可能敏感：

1.  The language of the prompt
2.  The language of the few-shot exemplars
3.  The ordering of few-shot exemplars
4.  The labels of the few-shot exemplars

大白话：

> **Task 没变，只改 prompt 的"包装方式"，model performance
> 都可能明显变化。**

例如 examples 完全一样，仅仅改变排列顺序，也可能得到不同结果，这叫
**prompt order sensitivity**。

------------------------------------------------------------------------

## 10. Strategy 1：增加 Exemplars

课程建议：few-shot learning 中，更多 exemplars 通常会改善
performance，但存在 **diminishing returns**。

``` text
1 example
→ 5 examples
→ 20 examples
→ 100 examples

通常越来越好
但每多加一些 example 的额外收益会逐渐变小
```

更多 examples 能给 model 更多证据来判断：

-   task 是什么
-   format 是什么
-   labels 怎么用
-   edge cases 如何处理

------------------------------------------------------------------------

## 11. Strategy 2：Calibrate Before Use

假设 binary sentiment classification：

``` text
Positive
Negative
```

模型本身可能天然更喜欢某个 token：

``` text
P(Positive) = 0.70
P(Negative) = 0.30
```

即使 input 没提供足够 evidence。

这意味着 output probability 中可能包含 model 自身对 labels 的 **prior
bias**。

Calibration 的大白话：

> **先测一下模型本来偏爱哪个答案，然后在真正分类时纠正这种"偏心"。**

课程介绍的 *Calibrate Before Use* 方法通过对 logits 做 affine
transformation 来 counter inherent biases。

核心：

``` text
Raw scores
→ inherent label bias
→ calibration
→ reduce bias
→ more meaningful classification
```

------------------------------------------------------------------------

## 12. Multi-Step Reasoning

有些任务需要多个步骤。

例如：

``` text
Fernando brings 3 dozen bagels.
16 attendees each eat 2.
How many are left?
```

需要：

``` text
3 dozen = 36
16 × 2 = 32
36 - 32 = 4
```

直觉：

> **复杂 reasoning task 如果被拆成多个小步骤，LLM 往往更容易完成。**

------------------------------------------------------------------------

## 13. Chain-of-Thought (CoT) Prompting

课程定义：

> **Chain of thought = a series of intermediate reasoning steps
> generated before the final answer.**

Standard exemplar：

``` text
Q: Roger has 5 tennis balls...
A: The answer is 11.
```

CoT exemplar：

``` text
Q: Roger has 5 tennis balls...
A: Roger started with 5 balls.
   2 cans × 3 balls = 6 balls.
   5 + 6 = 11.
   The answer is 11.
```

区别：

``` text
Standard:
Question → Final Answer

CoT:
Question → Intermediate Steps → Final Answer
```

------------------------------------------------------------------------

## 14. Few-Shot CoT

Few-shot Chain-of-Thought：

``` text
Example 1:
Q → reasoning steps → answer

Example 2:
Q → reasoning steps → answer

New Question:
Q → ?
```

模型看到 worked reasoning examples 后，模仿这种 pattern 来解决新问题。

课程 slide 中，standard prompting 对苹果题给错答案，而 CoT prompting
通过中间计算得到正确答案。

------------------------------------------------------------------------

## 15. Zero-Shot Chain-of-Thought

一个重要发现：

> **不一定需要手工写 CoT examples。**

只在问题后加：

``` text
Let's think step by step.
```

就可能让大模型产生 intermediate reasoning steps。

``` text
Question
+ "Let's think step by step."
→ reasoning steps
→ final answer
```

这叫 **Zero-Shot CoT**，因为：

``` text
0 worked examples
+ reasoning instruction
```

课程强调它的一个优势：同一个 task-agnostic phrase 可以用于很多不同
tasks，而不用为每个 task 手工设计 reasoning examples。

课程也指出，如果 Few-Shot CoT examples 的 question type 与实际 task
不匹配，performance 可能下降。

------------------------------------------------------------------------

## 16. Zero-Shot CoT 的 Two-Prompt Method

课程 slide 展示经典两步流程。

### Prompt 1：Reasoning Extraction

``` text
Question:
On average Joe throws 25 punches per minute.
A fight lasts 5 rounds of 3 minutes.
How many punches did he throw?

Let's think step by step.
```

Model 生成：

``` text
1 minute → 25
3 minutes → 75
5 rounds → 5 × 75 = 375
```

### Prompt 2：Answer Extraction

再把 question + reasoning 给模型，并要求类似：

``` text
Therefore, the answer (arabic numerals) is
```

得到：

``` text
375
```

所以：

``` text
Prompt 1: Question → Reasoning
Prompt 2: Question + Reasoning → Final Answer
```

课程特别强调：

``` text
No training
No examples
No gradient updates
```

------------------------------------------------------------------------

## 17. CoT 在什么任务上特别有帮助？

课程 slides 列出：

-   Arithmetic word problems
-   Symbolic manipulation
-   Logical / multi-step reasoning
-   Commonsense reasoning examples

共同点：

``` text
不能简单一步映射到答案
→ 需要 intermediate steps
```

课程还强调：

> **Gains appear in large models and barely help small ones.**

所以 CoT 不是魔法；model 本身需要具备足够的 underlying capability。

------------------------------------------------------------------------

## 18. Test-Time Compute Scaling

普通 inference：

``` text
Question
→ relatively direct generation
→ Answer
```

如果允许模型在回答前投入更多 computation：

``` text
Question
→ more reasoning / attempts / checking
→ Answer
```

这就是一种 **test-time compute scaling**。

大白话：

> **模型已经训练完了，但考试时允许它"多花点时间、多算一会儿"。**

增加的是：

``` text
inference/test-time compute
```

而不是 training compute。

------------------------------------------------------------------------

## 19. Self-Consistency：Test-Time Compute Scaling 的例子

课程 takeaway 提到：

> spend more compute per question, e.g. via self-consistency.

概念上，不只生成一条 reasoning path：

``` text
Question
→ path A → 42
```

而是多次：

``` text
Question
├→ path A → 42
├→ path B → 42
├→ path C → 39
├→ path D → 42
└→ path E → 40
```

再利用多个 paths 的结果选择更一致的答案：

``` text
42 appears most consistently
→ choose 42
```

核心：

> **同一个问题花更多 inference compute，探索多个 reasoning
> paths，再聚合结果。**

------------------------------------------------------------------------

## 20. Strategy 4：把复杂 Task 拆成 Minimal Units

除了让一个 prompt 内部产生 reasoning，也可以从 pipeline
层面把大任务拆成多个 LLM calls。

课程例子：生成 fictional person's Wikipedia-style article。

不要：

``` text
One giant prompt → Generate everything
```

而是：

``` text
Step 1: Generate a name
↓
Step 2: Generate birth/death dates
↓
Step 3: Generate profession/hometown
↓
Step 4: Generate biography
```

优点：

1.  Output 更容易 parse
2.  每个 prompt 更简单、更短
3.  减少 ambiguity/confusion
4.  每一步都可以 evaluate/refine
5.  中间可以人工 intervention

------------------------------------------------------------------------

## 21. Strategy 5：Use a Better-Trained Model

课程的现实结论：

> **提高 prompting 成功率最有效的方法之一，是使用训练得更好的 model。**

现代 models 相比早期 models：

``` text
better pretraining
+ more code/reasoning data
+ explicit instruction tuning
→ stronger instruction following
→ more robust to prompt variation
```

所以现代模型通常比早期 LLM 更容易 prompt。

## 23. Terms Cheat Sheet

### Emergence

Quantitative changes in a system result in qualitative changes in
behavior.

### Emergent Behavior

Abilities that larger models have and smaller models don't.

### In-Context Learning

Model uses instructions/examples in the prompt to perform a task without
parameter updates.

### Zero-Shot Learning

ICL with **zero exemplars**.

### Few-Shot Learning

ICL with **several exemplars**.

### Prompt Engineering

Try different prompt designs to find one that works well.

### Verbalizer

The template used to wrap/formulate an example for a task.

### Chain-of-Thought Prompting

Encourage intermediate reasoning steps before the final answer.

### Zero-Shot CoT

No worked examples; use a general reasoning cue such as "Let's think
step by step."

### Test-Time Compute Scaling

Spend more computation during inference rather than changing training,
for example multiple reasoning paths and self-consistency.

------------------------------------------------------------------------

## 24. Robustness：考试最容易问什么？

### Why can ICL be brittle?

> Performance can change substantially even when the underlying task is
> unchanged because LLMs can be sensitive to prompt language,
> demonstration language, demonstration order, labels, and formatting.

### How can we improve ICL?

课程主要策略：

``` text
1. Increase exemplars
2. Calibrate model predictions
3. Use multi-step / Chain-of-Thought reasoning
4. Divide complex tasks into minimal units
5. Use a better-trained model
```

------------------------------------------------------------------------

## 25. 和 Full Fine-Tuning 串起来

上一节：

``` text
每个 task 都 full fine-tune
→ expensive
→ many model copies
→ small-dataset overfitting
```

ICL 提供另一种思路：

``` text
Don't modify the model.
Tell the model what to do in context.
```

历史主线：

``` text
Task-specific model
→ Pretrained model + fine-tuning
→ Multi-task / instruction-tuned model
→ In-context learning:
   new task behavior from prompts/examples
   without retraining
```

这些方法不是严格互相替代。现代 LLM 通常已经经过 pretraining 和
instruction tuning，而用户在 inference 时继续通过 zero-shot/few-shot
prompting 使用 ICL。

------------------------------------------------------------------------

# 26. 最终大白话总结

如果只记 5 句话：

1.  **ICL 不更新 model weights；任务信息放在 prompt/context 里。**
2.  **Zero-shot = 没 examples；Few-shot = prompt 里给几个 examples。**
3.  **ICL 很强但可能 brittle：prompt language、example order、labels
    等小变化都可能影响结果。**
4.  **Chain-of-Thought 的核心是在 final answer 前产生 intermediate
    reasoning steps，尤其适合 arithmetic、symbolic 和 multi-step logical
    reasoning。**
5.  **Test-time compute scaling = 模型训练完后，在 inference
    时为难题投入更多计算，例如尝试多个 reasoning paths /
    self-consistency。**

最核心对比：

``` text
Fine-tuning:
改变 weights，让模型学任务

In-context learning:
不改变 weights，
把 instruction/examples 放进 context，
让模型现场完成任务
```
