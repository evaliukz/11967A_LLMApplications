# A Survey on Data Selection for Language Models --- 大白话精讲笔记

**Paper:** Alon Albalak et al., *A Survey on Data Selection for Language
Models* (2024)\
**arXiv:** 2402.16827v1

## 1. 一句话说这篇论文在讲什么

这篇论文的核心问题不是"LLM 应该用多少数据？"，而是：

> **手里有海量数据，但 GPU
> 预算有限，到底应该让模型学哪些数据、丢掉哪些数据、哪些数据应该多学几遍？**

这就是 **Data Selection（数据选择）**。

``` text
Raw Data
   ↓
哪些值得学？
   ↓
Filter / Clean / Deduplicate / Score / Mix
   ↓
Selected Dataset
   ↓
Train LLM
```

核心思想：**More data 不一定等于 better
data。训练数据的组成和选择方式本身就是模型设计的一部分。**

## 2. 为什么 Data Selection 重要？

现代 LLM 的候选数据可能来自
Internet、Books、Code、Papers、Forums、Wikipedia 等，但 GPU compute
有限。如果把 spam、duplicates、wrong-language text、toxic
content、benchmark answers
和高质量文本一起无差别训练，它们都会消耗昂贵的 training compute。

所以真正的问题是：

``` text
有限的 GPU FLOPs
       ↓
应该花在哪些 tokens 上？
```

Data Selection 的目标可以包括：

-   提高 model performance
-   提高 data efficiency
-   降低训练成本
-   保证 evaluation integrity
-   减少 bias / toxicity
-   让数据匹配目标 domain

## 4. 全文最重要的统一框架

作者认为，大部分 Data Selection 方法都可以拆成：

``` text
Data Selection
=
Utility Function
+
Selection Mechanism
```

### Utility Function

大白话：**先给每条数据打分------"这东西有多值得学？"**

例如：

``` text
Wikipedia article → 0.95
spam advertisement → 0.05
Python tutorial → 0.90
```

评分依据可以是：

-   是不是目标语言？
-   像不像高质量 reference corpus？
-   perplexity 多高？
-   是否重复？
-   是否 toxic？
-   和目标 domain 像不像？
-   长度、标点、字符比例是否合理？

### Selection Mechanism

有了 score 后，还要决定怎么办。

最简单：

``` text
score > 0.8 → KEEP
score <= 0.8 → DROP
```

这是 deterministic filtering。

也可以：

``` text
score 越高 → sampling probability 越高
```

这是 stochastic selection。

所以：

``` text
Utility Function
= 这条数据值多少钱？

Selection Mechanism
= 根据这个价值，我怎么处理它？
```

## 5. 为什么不能总是一刀切？

假设你定义 Wikipedia-like = high quality，然后只保留最像 Wikipedia
的网页。最后可能全是正式百科语言，而
Reddit、口语、真实问答、长尾知识等都消失。

所以存在重要 trade-off：

``` text
Quality ↔ Diversity
```

Stochastic selection 有时比 hard threshold 更合理：

``` text
high score   → 大概率保留
medium score → 有一定概率保留
low score    → 小概率保留
```

这样不会因为一个 imperfect quality metric 把整个长尾 distribution
全砍掉。

## 6. Distribution Matching vs Diversification

### Distribution Matching

目标：**让 training data 更像未来真正关心的数据。**

例如 Medical LLM 可以优先 medical papers、medical textbooks 等。也可以把
Wikipedia 当作 high-quality reference，然后寻找 Common Crawl 中最像它的
documents。

### Diversification

目标：**不要让模型一直重复学习同一种东西。**

1000 篇几乎一样的新闻转载，通常不如覆盖 100
个不同主题和写法。Deduplication 就是典型 diversification 方法。

## 8. Language Filtering

第一步常常是判断：**这篇东西是什么语言？**

常见方法包括 character n-grams、fastText、langdetect 等。

为什么不用巨大 LLM 判断？因为要处理 billions of documents / trillions of
tokens。即使每篇多一点 compute，总成本也会极大。

所以这是 AI Infra 的经典 trade-off：

``` text
filter accuracy ↔ filtering compute
```

## 9. Heuristic Filtering

Heuristic 就是简单、便宜的人工规则：

``` text
document 太短 → DROP
数字比例太高 → DROP
重复字符太多 → DROP
全是大写 → DROP
缺少合理标点 → DROP
```

这些方法不聪明，但非常便宜、快、适合 web-scale data。

你的 `heuristic_quality_filter(text)` 正是在做这一类事情。

## 10. Data Quality Filtering

"高质量"很难客观定义。一种经典方法是把 Wikipedia、Books、WebText 等当作
high-quality reference corpus，然后训练 lightweight classifier 判断
candidate document 有多像 reference distribution。

注意：这其实不是发现宇宙中客观的"质量"，而是在定义一种 **desired
distribution**。

## 11. Perplexity-Based Quality Filtering

另一种方法：

``` text
在 reference corpus 上训练 LM
        ↓
candidate document
        ↓
calculate perplexity
```

如果 candidate 对 reference LM 来说 PPL 较低，说明它更像 reference
distribution。

关键 nuance：

> **Low perplexity 不等于客观意义上的"好"，更准确地说是"更像 reference
> model 学到的 distribution"。**

## 12. Domain-Specific Selection

如果目标是 Finance / Medical / Legal / Code LLM，可以给与目标 domain
更相似的数据更高 utility。

``` text
Candidate Document
       ↓
How similar to target domain?
       ↓
Utility Score
```

本质仍是 Distribution Matching。

## 13. Deduplication

互联网重复内容很多。同一新闻可能被几十个网站转载。

如果不 deduplicate：

``` text
同一段文字
→ 模型看到很多遍
```

问题包括：

1.  浪费 training compute
2.  增加 memorization
3.  减少 dataset coverage

因此 dedup 常带来：

``` text
less redundancy
→ better coverage
→ less wasted compute
→ potentially less memorization
```

常见方法：

``` text
URL matching
Hashing
String similarity
Model representations
MinHash / LSH
```

Exact duplicate 很简单；near duplicate 更难。

Dedup 也不是越狠越好。如果一个长 document 只有一小段重复，可以删除整个
document、只删 duplicated span，或者保留但不给 duplicated tokens 算
loss。每种方案都有 trade-off。

## 14. Toxic / Explicit Content Filtering

Data Selection 不只为了 performance，也可以为了减少 toxicity、harmful
content 和 bias。

但简单 keyword filtering 可能误删正常讨论。例如 academic discussion of
hate speech 可能包含 toxic words，却并不等于 harmful document。

所以：

``` text
contains toxic word
≠
should automatically be removed
```

## 15. Multilingual Data Selection

不能把 English filtering rules 原封不动复制给 Chinese。

例如相同内容下，Chinese 可能需要更少 characters。如果 minimum-character
threshold 按 English 调好，直接用于 Chinese，可能误删大量正常中文
documents。

所以：

> **Filtering hyperparameters often need to be language-specific.**

这也是 multilingual data pipeline bias 的来源之一。

## 16. Data Mixing

过滤完还要决定：**不同来源各占多少？**

例如：

``` text
Web        70%
Books      10%
Wikipedia   5%
Code       10%
Papers      5%
```

Raw dataset size 不等于 optimal importance。Wikipedia
可能很小但质量高，所以可以 oversample；Common Crawl 很大但可以
downsample。

本质：

``` text
Dataset A → sampling probability
Dataset B → sampling probability
Dataset C → sampling probability
```

因此 **data mixture weights 也是 training
hyperparameters**，而且最优比例可能依赖 tokenizer、dataset、model
architecture、optimizer 等。

## 17. Data Selection 不只发生在 Pretraining

论文覆盖：

``` text
Pretraining
Instruction Tuning
Alignment
In-Context Learning
Task-specific Fine-tuning
```

每个阶段目标不同。

Instruction tuning 可能更关心 instruction/task diversity、response
quality、difficulty、domain 和 license。

Alignment 的 preference data 更关心 helpfulness、safety、bias、toxicity
和 preference quality。

In-context learning 里，"few-shot prompt 到底放哪几个
examples？"本身也是 data selection：可以选最相似、最 diverse 或最
representative 的 examples。

## 18. Evaluation Contamination

假设 benchmark question 和答案已经出现在 pretraining
corpus。模型考试答对时，我们不知道它是真的会
reasoning，还是以前见过答案。

所以需要：

``` text
Test Set Decontamination

Training Data
↓
search benchmark overlap
↓
remove contaminated examples
```

否则 benchmark score 可能虚高。

## 19. Memorization 一定坏吗？

不一定。

例如 Pythagorean theorem：

``` text
a² + b² = c²
```

我们确实希望模型准确记住。

所以真正的问题不是：

``` text
memorization = bad
generalization = good
```

而是：

``` text
什么应该 memorized？
什么应该 generalized？
```

## 20. "There's No Free Lunch for Filtering"

这是全文很重要的思想。

任何 filtering 都可能：

``` text
remove bad data
+
accidentally remove useful data
```

例如只保留 Wikipedia-like English，可能提升 formal QA，却损失
slang、dialogue、minority dialects、informal language 和 long-tail
knowledge。

> **Filtering 永远是在改变 training distribution，而不只是"删除垃圾"。**

## 21. 为什么 Data Selection Research 很难？

怎么知道 Dataset A 比 Dataset B 好？

最可靠的办法通常是：

``` text
Train Model A on Dataset A
Train Model B on Dataset B
↓
Evaluate
```

但 pretraining 极贵。

所以：

``` text
改一个 filter
↓
重新训练 LM
↓
才能真正知道效果
```

这使大规模 data-selection research
很昂贵，也解释了为什么很多工业经验集中在少数拥有大量 compute 的组织中。

## 22. 未来方向：把 Compute 从 Training 移到 Data Processing

论文提出一个很有 AI Infra 味道的方向：

> **Shift compute from model training to data processing.**

传统：

``` text
Cheap Filtering
+
Huge Training Compute
```

未来可能：

``` text
Smarter / More Expensive Data Processing
+
Less but Better Training Data
+
More Efficient Training
```

例如用模型给 documents 打分、reward-model-style filtering、更复杂
dedup、更好的 domain matching。

如果 1 GPU-hour 的 filtering 能省 100 GPU-hours 的 training，就很值得。

## 23. AI Infra 视角

传统 scaling：

``` text
better model
=
more parameters
+
more tokens
+

```

Data-centric scaling：

``` text
better model
=
better architecture
+
better selected tokens
+
better use of compute
```

于是基础设施不仅有 Training FLOPs，还涉及：

``` text
Data Processing FLOPs
Storage
Distributed Filtering
Dedup Index
Dataset Versioning
Data Lineage
Sampling Infrastructure
```

## 24. 用"大学招生"理解全文

假设大学有 1000 万 applicants，但只能招 1 万人。

你会做：

``` text
Language Filtering
→ 是否满足基本语言要求？

Heuristic Filtering
→ 申请材料是不是明显垃圾？

Quality Filtering
→ 整体质量如何？

Domain Selection
→ 现在是不是特别缺 CS students？

Deduplication
→ 是否重复提交？

Diversification
→ 是否所有人背景都一样？

Data Mixing
→ CS / Biology / Economics 各招多少？
```

最终 Selected Student Body 决定学校是什么样。

同理：

> **Selected Training Corpus 很大程度决定 LLM 学成什么样。**

## 26. 面试版回答

> Data selection determines which candidate training examples should be
> included and how frequently they should be sampled. A typical
> pretraining pipeline combines language identification, heuristic and
> model-based quality filtering, domain selection, deduplication,
> toxicity filtering, and data mixture optimization. The goal is not
> simply to maximize dataset size, but to allocate limited training
> compute to data that best supports the target model behavior.

## 28. 最重要的 Trade-offs

``` text
Quality       ↔ Diversity
Accuracy      ↔ Filtering Cost
More Data     ↔ Better Data
Deduplication ↔ Useful Repetition
Safety        ↔ Coverage
Target Domain ↔ General Capability
Hard Filter   ↔ Stochastic Sampling
Memorization  ↔ Generalization
```

没有 universal best pipeline。它取决于：

``` text
What model are you building?
For whom?
For what tasks?
Under what compute budget?
```

## 29. 一分钟考试版

### Data Selection

决定：

``` text
1. 哪些数据训练
2. 哪些数据不训练
3. 哪些数据训练得更多
```

### 两个核心组件

``` text
Utility Function
= 数据价值打分

Selection Mechanism
= 根据分数 keep/drop/sample/repeat
```

### Pretraining Pipeline

``` text
Language
↓
Heuristics
↓
Quality
↓
Domain
↓
Dedup
↓
Toxicity
↓
Multilingual handling
↓
Data Mixing
```

### 最终目标

不是：

``` text
Train on as much data as possible
```

``` text
Use limited training compute
on the most useful distribution of data.
```
