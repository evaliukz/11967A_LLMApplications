# LLM Pre-training Data Case Studies: WebText vs Common Crawl

## 1. 这两个 Case Study 到底在讲什么？

前面我们已经知道，大模型需要海量训练数据，而高质量的
Wikipedia、书籍等数据很快就会用完，所以最终必须从 Web 获取大量数据。

真正困难的问题不是：

> Internet 上有没有足够多的文字？

而是：

> **这么大的 Internet，我到底应该抓哪些网页？**

WebText 和 Common Crawl 给出了两种完全不同的答案：

``` text
WebText:
让 Reddit 用户帮助发现和筛选 URL

Common Crawl:
从 Seed URLs 出发，让 Web Crawler 沿着 hyperlink graph 不断探索
```

它们最重要的共同点是：

> **URL selection 本身就会改变最终训练数据的 distribution，并引入
> bias。**

------------------------------------------------------------------------

# 2. Case 1: WebText

WebText 是 GPT-2 使用的 pre-training dataset。

它的核心思路非常直观：

> 与其自己判断整个 Internet 上什么网页质量高，不如利用 Reddit
> 用户已经提供的 human quality signal。

## 2.1 WebText 的数据收集流程

OpenAI 收集 Reddit 用户发布的 outbound links，然后使用
Karma（upvotes）进行初步质量筛选。

``` text
Reddit outbound links
        ↓
约 45 million links
        ↓
只保留 Karma > 3 的 links
        ↓
Deduplicate URLs
        ↓
约 8 million web pages
        ↓
WebText
        ↓
GPT-2 pre-training
```

这里的关键思想是：

**Karma 被当作一个粗略的 quality proxy。**

大白话：

> 如果有人愿意把这个网页分享到
> Reddit，而且还有其他人点赞，那么这个网页大概率比从整个 Internet
> 随机抓到的页面更有价值。

这实际上解决了 Web crawling 中一个很困难的问题：

> **How do we select high-quality URLs?**

------------------------------------------------------------------------

# 3. WebText 的问题：Selection Bias

问题在于：

> **你让谁帮你筛数据，你的数据最终就会长得像谁。**

Reddit 用户并不是全世界人口的随机样本。

课程指出 Reddit 用户群：

-   更年轻
-   更 tech-savvy
-   English-centric
-   老年人等群体 representation 较低
-   low-resource languages representation 较低

因此 WebText 的 sampling pipeline 实际上是：

``` text
Internet
   ↓
Reddit users
   ↓
第一层 Selection Bias
   ↓
Users choose which URLs to post
   ↓
Karma > 3
   ↓
第二层 Selection Bias
   ↓
WebText
```

所以 WebText 并不是：

> Internet 上最好的内容

而更接近：

> **Reddit 用户愿意分享，而且 Reddit community 比较喜欢的 Internet
> 内容。**

------------------------------------------------------------------------

# 4. Karma ≠ Quality

Karma 是一个 useful signal，但它并不是严格意义上的 content quality
metric。

一个网页得到很多 upvotes，只说明：

> 某个 Reddit community 喜欢它。

并不能保证它：

-   factual
-   educational
-   unbiased
-   safe
-   适合 LLM pre-training

因此这里有一个非常重要的 LLM data principle：

> **Every quality signal introduces its own bias.**

如果使用 Reddit Karma 作为 quality proxy，就会把 Reddit community
的偏好一起带入 dataset。

------------------------------------------------------------------------

# 5. 为什么今天很难重新构建 WebText？

课程指出，当年 WebText 使用的这种方法今天已经很难直接复制，因为 Reddit
不再允许过去那种免费的 public scraping。

随着 LLM 对数据需求越来越大：

``` text
Internet Data
      ↓
becomes valuable for AI training
      ↓
Platforms restrict scraping
      ↓
API / licensing agreements
      ↓
Training data becomes more expensive
```

因此现代 LLM 的一个重要挑战是：

> **High-quality Internet training data is becoming harder and more
> expensive to obtain.**

------------------------------------------------------------------------

# 6. Case 2: Common Crawl

Common Crawl 是一个 nonprofit organization，提供公开的大规模 Web crawl
数据。

它和 WebText 的方法完全不同。

WebText：

``` text
Reddit users
    ↓
discover URLs
```

Common Crawl：

``` text
Seed URLs
    ↓
follow hyperlinks
    ↓
discover new URLs
    ↓
follow hyperlinks again
    ↓
continue crawling
```

这就是传统的 **Web Crawler**。

------------------------------------------------------------------------

# 7. Common Crawl 的基本流程

假设 crawler 从一个大学网站开始：

``` text
MIT.edu
   ↓
links → A, B, C

A
↓
links → D, E, F

D
↓
links → G, H ...
```

Crawler 不断：

1.  下载网页
2.  提取 hyperlinks
3.  把新 URL 放入待抓取队列
4.  选择下一批 URL
5.  继续 crawl

可以抽象成：

``` text
Seed URLs
     ↓
URL Discovery
     ↓
URL Frontier
     ↓
Crawler Workers
     ↓
Downloaded HTML
     ↓
Extract Links
     ↓
New URLs
     └──────────────→ URL Frontier
```

这里的 **URL Frontier** 就是：

> 已经发现，但是还没有 crawl 的 URL 集合 / 调度系统。

真正困难的问题是：

> **Frontier 里面可能有几十亿 URL，下一步到底 crawl 哪一个？**

------------------------------------------------------------------------

# 8. Common Crawl 的规模

根据课程材料：

-   大约每两个月发布一次新的 web crawl
-   每次记录约 **3 billion web pages**
-   2008--2021 年间累计捕获约 **220 billion web pages**
-   每次 crawl 大约 follow **500 billion links**
-   其中约 **25 billion** 是首次遇到的 unique pages

这说明一个非常重要的问题：

> **Crawler 发现的 URL 数量远远大于它最终有资源真正下载的 URL 数量。**

所以 crawler 必须进行：

``` text
URL prioritization
URL scheduling
crawl budget allocation
```

------------------------------------------------------------------------

# 9. Common Crawl ≠ 整个 Internet

这是一个非常容易产生的误解。

Common Crawl 很大，但：

> **Common Crawl 不是 Internet 的完整 copy。**

因为 crawler 永远受到：

-   compute budget
-   storage budget
-   bandwidth
-   crawl scheduling
-   robots rules
-   URL prioritization

等限制。

因此：

``` text
Entire Internet
      ↓
Crawler sampling
      ↓
Common Crawl
```

Common Crawl 本质上仍然只是：

> **Internet 的一个 sample。**

------------------------------------------------------------------------

# 10. 一个核心系统问题：Freshness vs Coverage

Crawler 有固定 compute / bandwidth budget。

假设现在有两个 URL：

``` text
Option A:
Re-crawl cnn.com

Option B:
Crawl 一个从来没有访问过的网站
```

选择 A：

``` text
re-crawl existing pages
      ↓
better freshness
```

选择 B：

``` text
explore new pages
      ↓
better coverage
```

所以 crawler 永远存在一个 trade-off：

``` text
Freshness
   ↕
Coverage
```

也就是：

> **是重新抓旧网页，保证数据更新？还是探索新的 Web 区域？**

------------------------------------------------------------------------

# 11. 为什么这和 URL Frontier 有关系？

所有 discovered-but-not-yet-crawled URLs 都会进入 URL Frontier。

``` text
Discovered URLs
      ↓
   URL Frontier
      ↓
Priority / Scheduling
      ↓
Crawler Workers
```

URL Frontier 的 scheduler 实际上就在决定：

``` text
Which URL should be crawled next?
```

例如可能考虑：

-   URL quality
-   domain importance
-   last crawl time
-   crawl frequency
-   robots.txt
-   domain rate limits
-   freshness
-   estimated content value

因此：

> **URL Frontier 是 Web crawler 的核心 scheduling component。**

这和 distributed systems 里的 queue / scheduler / priority system 很像。

------------------------------------------------------------------------

# 12. Common Crawl 的 Historical Snapshots

Common Crawl 从 2008 年开始保存不同时间的 Web snapshots。

因此可以得到类似：

``` text
Web 2009
Web 2012
Web 2018
Web 2020
Web 2024
...
```

这对 LLM training 和 evaluation 很有价值。

例如，如果你想训练或测试：

> 一个只能知道 2019 年以前信息的模型

就可以使用历史 snapshot，减少 future information leakage。

------------------------------------------------------------------------

# 13. Historical Crawls 还可以改善 Low-resource Languages

假设最新一次 crawl 的语言分布是：

``` text
English       ███████████████████
Indonesian    ██
```

如果希望提高 Indonesian representation，可以：

``` text
English:
latest crawl only

Indonesian:
aggregate 5 years of crawls
        ↓
more Indonesian documents
```

因此 dataset builder 可以人为调整：

> **training data mixture**

这已经不是简单的 crawling，而是：

``` text
Dataset Composition
Data Mixture Design
Language Balancing
```

------------------------------------------------------------------------

# 14. Common Crawl 同样存在 Bias

Common Crawl 虽然不像 WebText 那样直接依赖 Reddit 用户，但它也不是
unbiased。

最终抓到哪些网页会受到：

``` text
Seed URLs
     ↓
Traversal Algorithm
     ↓
URL Prioritization
     ↓
Per-domain URL Cap
     ↓
Crawler Physical Location
     ↓
Final Crawled Dataset
```

------------------------------------------------------------------------

# 15. Seed URLs 会产生 Bias

Crawler 必须从某些网站开始。

例如：

``` text
.edu
.gov
Wikipedia
major news sites
```

如果 seed 本身偏向某些类型的网站，那么 crawler 沿 hyperlink graph
扩散后，最终 dataset 也会受到影响。

因为 Web 并不是一个完全随机连接的 graph。

------------------------------------------------------------------------

# 16. Per-domain URL Cap 为什么会影响 Dataset？

假设：

``` text
website A = 100 million pages
website B = 10,000 pages
```

如果完全按照网页数量 crawl：

``` text
website A
```

可能会占据 dataset 很大比例。

所以 crawler 可能设置：

``` text
per-domain URL cap
```

例如：

> 每个 domain 最多 crawl N 个 URL。

这样可以避免一个网站垄断 crawl budget。

但是：

> **任何 sampling rule 都会改变 dataset distribution。**

------------------------------------------------------------------------

# 17. Crawler Physical Location 也会影响数据

网站可能根据访问者的位置返回不同内容。

例如：

``` text
Crawler in US
     ↓
US version of website

Crawler in Europe
     ↓
EU version

Crawler in Asia
     ↓
different localized content
```

所以即使 URL 一样：

``` text
same URL
```

不同 crawler location 也可能得到不同 content。

------------------------------------------------------------------------

# 18. WebText vs Common Crawl

  -----------------------------------------------------------------------
                          WebText                 Common Crawl
  ----------------------- ----------------------- -----------------------
  URL discovery           Reddit outbound links   Seed URLs + hyperlink
                                                  traversal

  Quality signal          Karma \> 3              Crawl prioritization +
                                                  后续 filtering

  优点                    有 human-generated      超大规模、开放、长期
                          quality signal          historical crawls

  主要 Bias               Reddit demographics /   Seed / traversal /
                          English / Karma         domain cap / crawler
                                                  location

  Scale                   \~8M pages              \~3B pages per
                                                  crawl（课程数据）

  核心思想                Human-curated discovery Web-scale crawling
  -----------------------------------------------------------------------

------------------------------------------------------------------------

# 19. 整个 Pre-training Data Pipeline 应该怎么理解？

最重要的不是背 WebText 和 Common Crawl 的数字，而是理解：

> **Dataset 是一层一层被"选择"出来的。**

完整过程：

``` text
Raw Internet
     ↓
URL Discovery / Selection
     ↓
Selection Bias
     ↓
Crawling
     ↓
Sampling Bias
     ↓
HTML → Raw Text
     ↓
Filtering
     ↓
Quality / Safety Bias
     ↓
Deduplication
     ↓
Data Mixture Design
     ↓
Tokenization
     ↓
Batching
     ↓
Final Pre-training Corpus
     ↓
LLM Training
```

所以：

> **模型的 bias 并不是模型训练完成以后才突然出现。**

从：

``` text
Which URL should we crawl?
```

这个决定开始，dataset distribution 就已经在被塑造。

------------------------------------------------------------------------

# 20. 面试版总结

如果面试官问：

> What's the difference between WebText and Common Crawl?

可以回答：

> **WebText uses Reddit engagement as a proxy for content quality, while
> Common Crawl uses large-scale hyperlink traversal. WebText inherits
> Reddit's demographic and language biases, while Common Crawl's
> distribution is shaped by seed selection, crawl prioritization, domain
> caps, and crawler location.**

------------------------------------------------------------------------

``` text
WebText

Common Crawl

```

但两者都说明同一个核心原则：

> **How you collect data determines what the model learns.**

或者更系统一点：

> **Data collection is itself a sampling algorithm.**
