# BPE Tokenizer Code Walkthrough — 大白话 + 完整代码

## 1. 这份代码到底在干什么？

这份代码是在**自己实现一个 BPE（Byte Pair Encoding）Tokenizer**。

最核心的思想只有一句话：

> **一开始把文本拆得很细，然后不断把训练数据里最常一起出现的相邻 token 合并成一个新 token。**

代码实现了两个版本：

```text
ASCIIBPETokenizer
→ 初始 vocabulary = 128 个 ASCII characters
→ 比较适合先理解 BPE algorithm

UnicodeBPETokenizer
→ 初始 vocabulary = 256 个 UTF-8 bytes
→ 可以表示 Unicode 文本
→ 更接近现代 byte-level BPE 的思路
```

课程真正希望你理解的是：

```text
training:
text → initial token ids → count bigrams → merge frequent bigram → learn vocab + merge rules

inference / encode:
new text → initial token ids → replay learned merge rules → BPE token ids

decode:
token ids → vocab entries → original text
```

# 2. 先用一个超级小的例子理解 BPE

假设训练数据是：

```text
ababab
```

ASCII 中：

```text
'a' = 97
'b' = 98
```

所以一开始：

```python
token_ids = [97, 98, 97, 98, 97, 98]
```

相邻 bigrams 是：

```text
(97, 98)  → 3 次    # ab
(98, 97)  → 2 次    # ba
```

最频繁的是：

```text
(97, 98)
```

于是 BPE 创建一个新 token：

```text
new token id = 128
new token = "ab"
```

因为原始 ASCII vocab 已经有：

```text
0 ... 127
```

所以第一个新 token id 就是 128。

然后：

```text
[97,98,97,98,97,98]

        ↓ merge (97,98)

[128,128,128]
```

此时 vocabulary 变成：

```text
...
97  → "a"
98  → "b"
...
128 → "ab"
```

并且记下一条 rule：

```python
merge_rules[(97, 98)] = 128
```

如果继续做第二次 merge：

```text
[128,128,128]
```

bigram：

```text
(128,128) → 2 次
```

于是创建：

```text
129 → "abab"
```

replace 时注意 **non-overlapping replacement**：

```text
[128,128,128]
→ [129,128]
```

而不是把两个 overlapping `(128,128)` 都同时替换。

# 5. `string_to_unicode_bytes`

原代码的 type annotation 写的是 `-> bytes`，但实际返回：

```python
list(s.encode("utf-8"))
```

所以实际类型是：

```python
list[int]
```

更一致的写法应该是：

```python
def string_to_unicode_bytes(s: str) -> list[int]:
    return list(s.encode("utf-8"))
```

例如 ASCII 字符：

```python
string_to_unicode_bytes("A")
# [65]
```

Unicode 字符可能需要多个 UTF-8 bytes，例如一个中文字符不会只对应一个 0–255 的整数。

这里最重要的思想是：

> **byte-level tokenizer 不需要为世界上每一个 Unicode character 单独准备初始 token；只要 256 个 byte values 就能表示 UTF-8 文本。**

# 6. `compute_bigram_statistics`

```python
def compute_bigram_statistics(token_ids, counter=None):
    bigram_counter = Counter() if counter is None else counter

    for left, right in zip(token_ids, token_ids[1:]):
        bigram_counter[(left, right)] += 1

    return bigram_counter
```

这是 BPE training 最核心的 helper 之一：

> **数每一对相邻 tokens 出现多少次。**

例如：

```python
token_ids = [1, 2, 3, 1, 2, 3]
```

这里：

```python
token_ids
# [1,2,3,1,2,3]

token_ids[1:]
# [2,3,1,2,3]
```

`zip(...)` 得到：

```text
(1,2)
(2,3)
(3,1)
(1,2)
(2,3)
```

所以 Counter 是：

```python
{
    (1, 2): 2,
    (2, 3): 2,
    (3, 1): 1,
}
```

### 为什么函数允许传入 `counter`？

Unicode tokenizer 把文本拆成多个 spans 后，需要：

```text
span 1 → count
span 2 → add into same Counter
span 3 → add into same Counter
```

所以可以复用同一个 Counter 累加 statistics。

# 7. `replace_bigram`

```python
def replace_bigram(token_ids, bigram, bigram_id):
    idx = 0
    new_token_ids = []

    while idx < len(token_ids):
        if token_ids[idx : idx + 2] == list(bigram):
            new_token_ids.append(bigram_id)
            idx += 2
        else:
            new_token_ids.append(token_ids[idx])
            idx += 1

    return new_token_ids
```

它的工作是：

> **把 sequence 里所有 non-overlapping 的指定 bigram 换成一个新 token。**

例如：

```python
token_ids = [97,98,97,98,97]
bigram = (97,98)
bigram_id = 128
```

执行过程：

```text
idx = 0
看到 [97,98]
→ match
→ append 128
→ idx += 2

idx = 2
又看到 [97,98]
→ append 128
→ idx += 2

idx = 4
只剩 97
→ append 97
```

结果：

```python
[128, 128, 97]
```

### 为什么 match 后是 `idx += 2`？

因为两个旧 tokens 已经一起被一个新 token 吃掉了。

# 9. TODO 1 — `ASCIIBPETokenizer.merge()`

目标分两步：

```text
1. 找出现次数最多的 bigram
2. 创建新 token，并把所有这个 bigram 替换掉
```

题目还要求：

> 如果 frequency 相同，选择 lexicographically smaller bigram。

例如：

```python
(1, 5): 3
(1, 3): 3
```

频率一样时：

```text
(1,3) < (1,5)
```

所以选 `(1,3)`。

可以用：

```python
min(
    bigram_counter,
    key=lambda bigram: (-bigram_counter[bigram], bigram),
)
```

为什么是 `min`？

我们希望：

```text
frequency 最大
```

所以先取：

```python
-frequency
```

频率越大，负数越小。

例如：

```text
frequency 10 → -10
frequency  5 → -5
```

`min` 会选 `-10`。

如果 frequency 相同，就继续比较 tuple 本身，实现 lexicographical tie-breaking。

完整实现：

```python
def merge(self, token_ids: list[int]) -> list[int]:
    bigram_counter = compute_bigram_statistics(token_ids)

    if not bigram_counter:
        return token_ids

    bigram_to_merge = min(
        bigram_counter,
        key=lambda bigram: (-bigram_counter[bigram], bigram),
    )

    token_left, token_right = bigram_to_merge

    new_token = self.vocab[token_left] + self.vocab[token_right]
    new_token_id = len(self.vocab)

    self.vocab.append(new_token)
    self.merge_rules[bigram_to_merge] = new_token_id

    return replace_bigram(token_ids, bigram_to_merge, new_token_id)
```

### 用 `ababab` 跑一次

```python
self.vocab[97] = "a"
self.vocab[98] = "b"

token_ids = [97,98,97,98,97,98]
```

statistics：

```python
(97,98): 3
(98,97): 2
```

选择：

```python
bigram_to_merge = (97,98)
```

创建：

```python
new_token = "a" + "b" = "ab"
new_token_id = 128
```

记录：

```python
self.vocab[128] = "ab"
self.merge_rules[(97,98)] = 128
```

返回：

```python
[128,128,128]
```

# 10. `from_data()` = 训练 tokenizer

```python
@classmethod
def from_data(cls, train_data: str, n_merges: int):
    tokenizer = cls()
    token_ids = string_to_ascii(train_data)

    for _ in range(n_merges):
        token_ids = tokenizer.merge(token_ids)

    return tokenizer
```

这就是整个 BPE training loop。

例如：

```python
tokenizer = ASCIIBPETokenizer.from_data(
    "ababab",
    n_merges=2,
)
```

初始：

```text
[97,98,97,98,97,98]
```

Merge 1：

```text
(97,98) → 128 = "ab"

[128,128,128]
```

Merge 2：

```text
(128,128) → 129 = "abab"

[129,128]
```

最终学到：

```python
merge_rules = {
    (97,98): 128,
    (128,128): 129,
}
```

以及：

```text
128 → "ab"
129 → "abab"
```

注意：**training 完成后并不需要保存训练 corpus 的最终 token_ids。真正重要的是学到的 `vocab` 和 `merge_rules`。**

# 11. TODO 2 — `encode()`

现在 tokenizer 已经训练好了。

假设：

```python
merge_rules = {
    (97,98): 128,     # ab
    (128,128): 129,   # abab
}
```

现在：

```python
encode("ababab")
```

首先回到 initial representation：

```python
[97,98,97,98,97,98]
```

然后**按照训练时学到的 merge rule 顺序 replay merges**。

第一条：

```text
(97,98) → 128
```

得到：

```python
[128,128,128]
```

第二条：

```text
(128,128) → 129
```

得到：

```python
[129,128]
```

因此：

```python
encode("ababab") == [129,128]
```

完整实现：

```python
def encode(self, text: str) -> list[int]:
    assert all(ord(c) < 128 for c in text), "input text is not ASCII"

    token_ids = string_to_ascii(text)

    for bigram, bigram_id in self.merge_rules.items():
        token_ids = replace_bigram(token_ids, bigram, bigram_id)

    return token_ids
```

### 为什么不能重新寻找“当前最频繁 bigram”？

因为 `encode()` 不是重新训练。

训练阶段：

```text
learn merge rules
```

Inference：

```text
apply already learned merge rules
```

所以千万不要在 `encode()` 里重新：

```python
compute most frequent bigram
```

否则新文本会自己发明新的 tokenizer rules，token IDs 就失去固定含义了。

# 12. Merge Rule 的顺序为什么重要？

BPE merge 是 sequential 的。

例如：

```python
(97,98) → 128
(128,128) → 129
```

第二条 rule 中的 token `128` 是第一条 merge 之后才存在的。

因此必须：

```text
先 97+98 → 128
再 128+128 → 129
```

不能反过来。

现代 Python `dict` 保留 insertion order，因此这里按 `self.merge_rules.items()` 遍历可以 replay training 时插入 merge rules 的顺序。

# 13. TODO 3 — `decode()`

假设：

```python
[129,128]
```

vocab 是：

```text
129 → "abab"
128 → "ab"
```

decode 只需要：

```text
"abab" + "ab"
= "ababab"
```

所以：

```python
def decode(self, token_ids: list[int]) -> str:
    return "".join(self.vocab[token_id] for token_id in token_ids)
```

这一步为什么这么简单？

因为每次创建 merged token 时，我们已经保存了它对应的完整 string：

```python
new_token = self.vocab[token_left] + self.vocab[token_right]
```

所以 vocab 本身已经知道每个 token 应该还原成什么文本。

# 14. ASCII BPE 完整核心逻辑

```text
TRAINING

"ababab"
    ↓ ASCII
[97,98,97,98,97,98]
    ↓ count bigrams
(97,98)=3
(98,97)=2
    ↓ merge
128 = "ab"
    ↓
[128,128,128]
    ↓ merge again
129 = "abab"
    ↓
[129,128]

Learned:
(97,98)   → 128
(128,128) → 129
```

然后 inference：

```text
ENCODE

"ababab"
    ↓ ASCII
[97,98,97,98,97,98]
    ↓ replay rule 1
[128,128,128]
    ↓ replay rule 2
[129,128]
```

Decode：

```text
[129,128]
    ↓ vocab lookup
["abab", "ab"]
    ↓ join
"ababab"
```

最重要的 invariant：

```python
decode(encode(text)) == text
```

对于合法输入应该成立。

训练 tokenizer 真正需要保存的是：


`save()` 把它们写到 JSON。

概念上可能类似：

```json
{

```

`from_config()` 做反方向：

```text
JSON

restore merge_rules

Tokenizer
```

这样不需要每次启动程序都重新 train tokenizer。

# 16. Unicode BPE 和 ASCII BPE 最大区别

ASCII tokenizer 初始 vocab：

```python
[chr(i) for i in range(128)]
```

所以每个初始 token 是一个 ASCII character。

Unicode tokenizer：

```python
self.vocab = [int.to_bytes(i) for i in range(256)]
```

每个初始 token 是一个 **byte**。

所以：

```text
ASCII BPE
character → token

Unicode byte-level BPE
UTF-8 byte → token
```

Unicode 版本 merge 时：

```python
new_token = self.vocab[token_left] + self.vocab[token_right]
```

这里做的是 bytes concatenation。

最后 decode：

```python
b"".join(...).decode("utf-8")
```

先把 bytes 拼回来，再 UTF-8 decode 成 Python string。

# 17. Unicode 为什么先切 `spans`？

代码使用：

```python
self.compiled_pattern = re.compile(r"(\s+\S*)")
```

然后：

```python
re.findall(self.compiled_pattern, train_data)
```

按照这份代码的设计，它试图把 whitespace 和后面的 non-whitespace 内容组成 chunk/span。

例如带空格的文本会被分成多个 spans，然后：

```python
span_token_ids = [
    string_to_unicode_bytes(span)
    for span in ...
]
```

训练时 bigram statistics 会跨 spans 累加：

```python
for token_ids in spans:
    bigram_counter = compute_bigram_statistics(
        token_ids,
        bigram_counter,
    )
```

但是 merge replacement 只发生在各自 span 内：

```python
return [
    replace_bigram(token_ids, bigram_to_merge, new_token_id)
    for token_ids in spans
]
```

所以不会直接创建跨 span boundary 的 merged token。

# 19. Unicode `encode()` 为什么看起来复杂一点？

核心还是：

```text
text
→ split into chunks
→ UTF-8 bytes
→ replay learned merges
```

代码先统计当前 chunk 里有哪些 bigrams：

```python
bigram_stats = compute_bigram_statistics(token_ids)
```

只要当前 sequence 中还存在某条 learned merge rule：

```python
while bigram_stats.keys() & self.merge_rules.keys():
```

就按照 `merge_rules` 的训练顺序寻找第一条当前可用 rule：

```python
for bigram, bigram_id in self.merge_rules.items():
    if bigram_stats[bigram] > 0:
        token_ids = replace_bigram(...)
        break
```

然后重新计算 bigrams，因为 merge 以后 sequence 已经变了。

# 21. 补全后的完整代码

```python
import json
import sys
from collections import Counter
from typing import TypeAlias

import regex as re
from tqdm.auto import trange

Bigram: TypeAlias = tuple[int, int]


def string_to_ascii(s: str) -> list[int]:
    return list(s.encode("ascii"))


def string_to_unicode_bytes(s: str) -> list[int]:
    return list(s.encode("utf-8"))


def compute_bigram_statistics(
    token_ids: list[int],
    counter: Counter | None = None,
) -> Counter[Bigram, int]:
    bigram_counter = Counter() if counter is None else counter

    for left, right in zip(token_ids, token_ids[1:]):
        bigram_counter[(left, right)] += 1

    return bigram_counter


def replace_bigram(
    token_ids: list[int],
    bigram: Bigram,
    bigram_id: int,
) -> list[int]:
    idx = 0
    new_token_ids = []

    while idx < len(token_ids):
        if token_ids[idx : idx + 2] == list(bigram):
            new_token_ids.append(bigram_id)
            idx += 2
        else:
            new_token_ids.append(token_ids[idx])
            idx += 1

    return new_token_ids


class ASCIIBPETokenizer:
    def __init__(self):
        self.vocab: list[str] = [chr(i) for i in range(128)]
        self.merge_rules: dict[Bigram, int] = {}

    def merge(self, token_ids: list[int]) -> list[int]:
        bigram_counter = compute_bigram_statistics(token_ids)

        # No adjacent pair remains.
        if not bigram_counter:
            return token_ids

        # Highest frequency first; lexicographically smaller pair wins ties.
        bigram_to_merge = min(
            bigram_counter,
            key=lambda bigram: (-bigram_counter[bigram], bigram),
        )

        token_left, token_right = bigram_to_merge
        new_token = self.vocab[token_left] + self.vocab[token_right]
        new_token_id = len(self.vocab)

        self.vocab.append(new_token)
        self.merge_rules[bigram_to_merge] = new_token_id

        return replace_bigram(token_ids, bigram_to_merge, new_token_id)

    def encode(self, text: str) -> list[int]:
        assert all(ord(c) < 128 for c in text), "input text is not ASCII"

        token_ids = string_to_ascii(text)

        # Replay learned merges in training order.
        for bigram, bigram_id in self.merge_rules.items():
            token_ids = replace_bigram(token_ids, bigram, bigram_id)

        return token_ids

    def decode(self, token_ids: list[int]) -> str:
        return "".join(self.vocab[token_id] for token_id in token_ids)

    @classmethod
    def from_config(cls, config_file: str):
        with open(config_file, "r") as f:
            config = json.load(f)

        tokenizer = cls()
        tokenizer.vocab = config["vocab"]
        tokenizer.merge_rules = {
            tuple(bigram): bigram_id
            for bigram, bigram_id in config["merge-rules"]
        }
        return tokenizer

    def save(self, path: str) -> None:
        config = {
            "vocab": self.vocab,
            "merge-rules": [
                [bigram, bigram_id]
                for bigram, bigram_id in self.merge_rules.items()
            ],
        }

        with open(path, "w") as f:
            json.dump(config, f, indent=2)

    @classmethod
    def from_data(cls, train_data: str, n_merges: int):
        tokenizer = cls()
        assert all(ord(c) < 128 for c in train_data), "train_data is not ASCII"

        token_ids = string_to_ascii(train_data)

        for _ in trange(n_merges, desc="merging..", file=sys.stdout):
            # Stop gracefully if the sequence has fewer than 2 tokens.
            if len(token_ids) < 2:
                break
            token_ids = tokenizer.merge(token_ids)

        return tokenizer


class UnicodeBPETokenizer:
    def __init__(self):
        self.vocab: list[bytes] = [int.to_bytes(i) for i in range(256)]
        self.merge_rules: dict[Bigram, int] = {}
        self.compiled_pattern = re.compile(r"(\s+\S*)")

    def merge(self, spans: list[list[int]]) -> list[list[int]]:
        bigram_counter = Counter()

        for token_ids in spans:
            bigram_counter = compute_bigram_statistics(
                token_ids,
                bigram_counter,
            )

        if not bigram_counter:
            return spans

        bigram_to_merge = min(
            bigram_counter,
            key=lambda tup: (-bigram_counter[tup], tup),
        )

        token_left, token_right = bigram_to_merge
        new_token = self.vocab[token_left] + self.vocab[token_right]
        new_token_id = len(self.vocab)

        self.vocab.append(new_token)
        self.merge_rules[bigram_to_merge] = new_token_id

        return [
            replace_bigram(token_ids, bigram_to_merge, new_token_id)
            for token_ids in spans
        ]

    def encode(self, text: str) -> list[int]:
        encoded = []

        for chunk in re.findall(self.compiled_pattern, text):
            token_ids = string_to_unicode_bytes(chunk)
            bigram_stats = compute_bigram_statistics(token_ids)

            while bigram_stats.keys() & self.merge_rules.keys():
                for bigram, bigram_id in self.merge_rules.items():
                    if bigram_stats[bigram] > 0:
                        token_ids = replace_bigram(
                            token_ids,
                            bigram,
                            bigram_id,
                        )
                        break

                bigram_stats = compute_bigram_statistics(token_ids)

            encoded.extend(token_ids)

        return encoded

    def decode(self, token_ids: list[int]) -> str:
        return b"".join(
            self.vocab[token_id] for token_id in token_ids
        ).decode("utf-8", errors="ignore")

    @classmethod
    def from_config(cls, config_file: str):
        with open(config_file, "r") as f:
            config = json.load(f)

        tokenizer = cls()
        tokenizer.vocab = [bytes(a) for a in config["vocab"]]
        tokenizer.merge_rules = {
            tuple(bigram): bigram_id
            for bigram, bigram_id in config["merge-rules"]
        }
        return tokenizer

    def save(self, path: str) -> None:
        config = {
            "vocab": [list(b) for b in self.vocab],
            "merge-rules": [
                [bigram, bigram_id]
                for bigram, bigram_id in self.merge_rules.items()
            ],
        }

        with open(path, "w") as f:
            json.dump(config, f, indent=2)

    @classmethod
    def from_data(cls, train_data: str, n_merges: int):
        tokenizer = cls()

        span_token_ids: list[list[int]] = [
            string_to_unicode_bytes(span)
            for span in re.findall(tokenizer.compiled_pattern, train_data)
        ]

        for _ in trange(n_merges, desc="merging..", file=sys.stdout):
            if not any(len(span) >= 2 for span in span_token_ids):
                break
            span_token_ids = tokenizer.merge(span_token_ids)

        return tokenizer
```

# 23. 这份作业真正应该理解什么？

不要把重点放在记 Python syntax。

真正应该掌握的是：

### Training

```text
initial fine-grained tokens
        ↓
count adjacent pairs
        ↓
find most frequent pair
        ↓
create a new token
        ↓
replace occurrences
        ↓
repeat
```

### Encoding

```text
new text
        ↓
initial byte / character IDs
        ↓
replay learned merge rules
        ↓
BPE token IDs
```

### Decoding

```text
BPE token IDs
        ↓
vocab lookup
        ↓
concatenate strings / bytes
        ↓
original text
```

一句话：

> **Training 是“学哪些 pair 值得合并”；encoding 是“把这些已经学好的合并规则应用到新文本”；decoding 是“根据 vocabulary 把 token IDs 拼回文本”。**

# 24. Interview / Exam Cheat Sheet

```text
BPE = Byte Pair Encoding

Goal:
frequent character/byte sequences
→ become single tokens

TRAINING:
1. Start with characters / bytes
2. Count adjacent token pairs
3. Select most frequent bigram
4. Create new token
5. Replace occurrences
6. Save merge rule
7. Repeat

Example:
"ababab"
→ [97,98,97,98,97,98]

(97,98) occurs 3 times
→ 128 = "ab"
→ [128,128,128]

(128,128) occurs 2 times
→ 129 = "abab"
→ [129,128]

ENCODE:
Do NOT learn new merges.
Replay learned merge rules in order.

DECODE:
lookup token IDs in vocab
→ concatenate

Important:
decode(encode(text)) == text

ASCII BPE:
initial vocab = 128 ASCII characters

Byte-level Unicode BPE:
initial vocab = 256 byte values
UTF-8 text can be represented with bytes

Key structures:
vocab[token_id] → token content
merge_rules[(left_id, right_id)] → merged_token_id

Why tie-breaking?
For deterministic training.

Why merge order matters?
Later tokens may depend on tokens created by earlier merges.
```

## 最后一句话

> **BPE tokenizer 的本质就是从最细的 character/byte tokens 开始，在训练 corpus 中不断寻找最常见的相邻 pair，把它们压缩成新的 token；最终 `vocab` 告诉我们每个 token 是什么，而 `merge_rules` 告诉我们 encode 新文本时应该按什么顺序把小 token 合成大 token。**
